# 10. 세계 여행 스테이지 (데이터 구조 · 확장 절차)

세계 여행 스테이지의 나라 구성 · 교육 메타 · 배경 데이터 SSOT. 게임 흐름(보스 격파 → 지도 → 목적지 선택 → 비행)은 docs/01_spec.md, 배경 이미지 생성 프롬프트는 docs/13_background-prompts.md 참조.

## 1. 구성 요약

1.1. 총 **59개 스테이지 = 54개 국가 + 5개 여행지**(발리·하와이·제주도·뉴욕·독도). "59개국"이라 부르지 않는다 - 여행지는 주권 국가가 아니라 소속 나라의 지리 여행지다. 독도는 한국의 동쪽 바다에 있는 화산섬 여행지로 표기한다.
1.2. 한 판은 `CFG.stageCount`(현재 40) 구역에서 끝난다. 나라 풀이 56개라 40구역 여정에 여유가 있다(이웃이 없으면 지도가 자동 진행).
1.3. 한국(서울)에서 출발해 대체로 서쪽으로 지구를 한 바퀴 돈다(아시아 → 중동·아프리카 → 유럽 → 아메리카 → 오세아니아 → 호주 종착).

## 2. 파일 분리 (관심사 분리)

데이터를 세 파일로 나눈다. 나라 식별자 `ko`(한국어 이름)를 공통 키로 이어 붙인다. 지도가 열릴 때마다 쓰이는 핫 데이터(라우팅)와, 교육 콘텐츠·배경 프롬프트처럼 성격이 다른 데이터를 한 파일에 섞지 않기 위함이다.

| 파일 | 역할 | 주요 필드 |
|---|---|---|
| `src/data/countries.js` | 지도·라우팅 전용 | ko, cap, lon, lat, cont, next, type, parentCountry, labelDir |
| `src/data/countries.education.js` | 교육 메타(교과 개념) | feature, eduKey, bgConcept, majorResources, colorAccent, note |
| `src/data/backgroundPools.js` | 공용 배경 풀 + 국가별 오버레이 | BG_POOLS(16종), COUNTRY_BG(59 매핑) |

2.1. **countries.js**: `type`은 `'country'`(주권 국가 54) 또는 `'travel'`(여행지 5)다. 여행지는 `parentCountry`(소속 나라)를 가지며, 사용자에게 보이는 모든 화면은 일반 국가도 여행지도 예외 없이 **윗줄 나라 / 아랫줄 목적지** 규격을 쓴다. 즉 일반 국가는 `국가명 / 수도`, 여행지는 `소속 국가 / 여행지 지역명`이다. `next`는 배열 정의 뒤 `[i+1..i+4]`를 자동 계산하며 배열 끝을 넘는 인덱스는 잘라낸다(범위 초과 원천 차단). `labelDir`는 붙어 있는 도시(싱가포르·말레이시아) 라벨 겹침 방지용.
2.2. **cont**는 `worldmap.js`의 대륙명(Asia/Africa/Europe/North America/South America/Oceania)과 일치해야 지도 대륙 하이라이트가 동작한다. 러시아는 영토 대부분이 아시아라 현 프로젝트 기준 `Asia`로 둔다.
2.3. **countries.education.js**: 한국 초·중·고 사회·지리 교과 대표 개념 중심. 수도 암기보다 지형·기후·산업·문화·환경·교통을 우선하고, 나라마다 학습 주제가 최대한 겹치지 않게 배분한다. 정치·종교·분쟁은 사실 중심 중립 표현만 쓴다.

## 3. 배경 재사용 구조 (공용 풀 + 오버레이)

국가별 완성 배경 56장을 만들지 않는다. **공용 기반 배경 16종(BG-01~16) + 국가별 오버레이**(랜드마크 실루엣·자연지형·포인트컬러) 조합으로 간다. 같은 풀에 나라가 몰리면(예: BG-12 유럽 9개국) 풀 주석의 `variants` 개념으로 오버레이·결을 분기해 단조로움을 관리한다.

3.1. 배경 설계 규칙: 종스크롤 무한 반복(seamless vertical loop), 플레이 가독성 우선(저채도·저대비, 강한 흰/검/네온 면적 금지), 랜드마크는 실루엣, 전경보다 원경. 국가 차이는 (1) 랜드마크 실루엣 (2) 자연지형·식생 (3) 포인트컬러 3가지로만 준다.
3.2. 실제 이미지는 아직 없다(placeholder). 생성용 프롬프트는 docs/13_background-prompts.md의 16풀별 텍스트를 이미지 생성 AI에 넣어 제작한다. 현재 인게임 배경 렌더(`view.js drawBackground`)는 서울 실루엣만 하드코딩돼 있고, 나머지 나라는 공용 우주·하늘 그라데이션 배경이다 - 풀/오버레이 이미지가 준비되면 그때 렌더에 연결한다.

## 4. 에셋 명명 규칙

- 공용 풀: `bg_pool_<ID>_<promptKey>` (예: `bg_pool_BG-01_eastasia_city_mountain`)
- 국가 오버레이: `overlay_<국가영문>_<요소>` (예: `overlay_korea_palace_roof`, `overlay_egypt_pyramid`, `overlay_bali_temple_gate`, `overlay_hawaii_volcano`)

## 5. 새 국가·여행지 추가 절차

## 4.1 지도 조작·중심

- 지도에는 홈으로 돌아가는 **나가기** 버튼이 있다.
- 나가기는 다른 화면과 같은 좌상단 뒤로가기 화살표이며, 일반 국가에는 수도를, 여행지에는 `소속 국가의 여행지`를 표시한다(제주도는 `한국의 여행지`).
- 지도 경도는 태평양이 중심에 오도록 반복 렌더한다. 오른쪽 끝을 지나 드래그하면 왼쪽 지도가 이어지고, 왼쪽 끝을 지나면 오른쪽 지도가 이어지는 수평 무한 순환 방식이다.

1. `countries.js` RAW 배열에 항목 추가(원하는 순서 위치). 일반국은 `T(ko, cap, lon, lat, cont)` 헬퍼, 여행지는 `{ ..., type:'travel', parentCountry }` 리터럴. next는 자동 재계산되므로 손대지 않는다.
2. `cont`가 worldmap.js에 있는 대륙명인지 확인. 그 나라 국경 path가 worldmap.js `COUNTRY_PATHS`에 있어야 대륙 색칠·선택 하이라이트가 동작한다. 없으면 지도 생성 스크립트(Natural Earth 110m 기반)로 재생성하거나 path를 추가한다. **ko 표기가 countries.js와 worldmap.js에서 정확히 일치해야 한다**(과거 "콩고 민주 공화국"↔"콩고민주공화국" 띄어쓰기 불일치로 선택 하이라이트가 안 되던 버그).
3. `countries.education.js`에 같은 ko 키로 교육 메타 6필드 추가.
4. `backgroundPools.js` `COUNTRY_BG`에 같은 ko 키로 풀·오버레이 매핑 추가(새 풀이 필요하면 BG_POOLS에 정의).
5. 검증: 세 파일의 ko 키 집합이 서로 일치하는지, 모든 `pool` 참조가 BG_POOLS에 있는지 확인.

## 6. 지도 데이터 출처

`worldmap.js` 국경 path는 Natural Earth 110m(퍼블릭 도메인)를 equirectangular 투영(viewBox 1000x500)으로 단순화해 생성한 것이다. 콩고민주공화국을 포함한 국가 영역은 모두 이 데이터에 들어 있다.

## 7. 디오라마 준비 도시 표시

7.1. 디오라마 배경 이미지가 준비된, 아직 방문하지 않은 도시는 도시 점(손가락 터치 원) 중앙에 별 도형을 겹쳐 표시한다. 별은 글꼴이 아닌 SVG 도형 중심으로 배치하고, 원과 대비되는 색을 써 작은 화면에서도 선명하게 구분한다. 해당 점을 그대로 눌러 목적지를 고를 수 있게 한다.
7.2. 이미 클리어해 여행 경로에 들어간 도시는 배경 이미지가 있어도 별을 표시하지 않는다.

## 7.3. 지도 선택 정보·지리 표기

- 지도 기본 화면은 후보 도시 핀만 표시한다. 핀을 터치하면 카드에 일반 국가는 `국가명 / 수도`, 여행지는 `소속 국가 / 여행지 지역명` 순으로 **설명어를 끼우지 않은 두 줄**로 표시하고, 카드의 `플레이`를 다시 눌러 비행·구역 진입을 확정한다. 이미 클리어한 곳은 지도 위에 같은 두 줄 규격으로 국가·수도(여행지는 소속 국가·여행지)를 표시한다. 지도 위 라벨과 선택·도착 카드 모두 상태와 무관하게 **나라명은 흰색**, **수도·여행지명은 연두색**이며 목적지 쪽을 나라명보다 조금 크게 표시한다. 보스 격파 후 돌아온 월드맵에서는 현재 위치도 같은 두 줄 라벨과 도착 파동·라벨 등장 효과를 표시한다.
- 확대할 때 후보 핀의 화면상 터치 크기는 기본 확대 크기를 넘지 않도록 역보정한다. 축소 시에는 기존처럼 작아진다.
- 여행 경로와 비행선은 경도 반복 지도에서 항상 가장 짧은 수평 경로를 선택한다. 서울↔하와이·뉴욕처럼 날짜변경선을 가로지르는 이동은 유럽을 돌아가지 않고 태평양을 직선 횡단한다.
- 선택 카드는 선택한 핀의 SVG 좌표를 기준으로 배치하며 드래그·확대·축소 때 계속 같은 핀을 따라간다. 선택 핀은 **기존 핀의 채움·외곽색을 절대 바꾸지 않고**, 핀 바깥에만 노란 도넛 링과 발광 효과를 별도 레이어로 더해 구분한다. 지도 바닥을 탭하거나 Esc를 누르면 선택·카드·링을 해제한다. 현재 위치에는 별도의 흰색·색상 배경이나 테두리 없이, 원본 비율을 보존한 바푸리 PNG 전체만 표시한다. 바푸리는 현재 도시의 노란 점과 겹치지 않게 그 점보다 화면상 10px 위에 둔다.
- 지도에는 5대양(태평양·대서양·인도양·북극해·남극해), 북극·남극, 적도선을 실제 위경도 좌표에 맞춰 크게 표기한다. 바다 이름과 극점 이름은 합치지 않는다. 북극은 정확한 북극점의 점에, 남극은 정확한 남극점 바로 위에 놓는다. 태평양 이름은 태평양 중앙(날짜변경선 부근)에 둔다. 대륙은 위·아래로 각각 지도 좌표 500만큼의 여백 안에서만 이동하고, 경로·비행 점선은 대륙 채움보다 앞 레이어에 그린다.

## 8. 목적지 전환 대기

8.1. 도시 선택 → 비행 → 도착 카드 뒤에는 선택한 도시의 디오라마 배경을 먼저 로드한다. 이미지가 준비되거나 파일 없음이 확인될 때까지 월드맵을 유지하며, 그동안 다음 구역의 전투·자동 발사는 시작하지 않는다.
8.2. 보스 사망은 주 폭발 1초와 마지막 파티클 소멸까지를 하나의 연출로 본다. 어떤 경우에도 2초 안에 보스·폭발 파티클·화면 섬광을 모두 정리한다. 도시 수호자가 동행 중이면 격파 즉시 작별 말풍선을 내고 5초 동안 화면 위로 빠르게 날아가 퇴장한 뒤에만 월드맵으로 넘어간다.

8.3. 도시 이름은 점수 문제가 아니라 조우 이벤트다. 목적지 도시 이름을 완성하면 도시명 라벨·하트 3개·소개 말풍선을 단 PNG 수호자가 보스전 끝까지 동행하며, 가장 가까운 적에게 계속 이어지는 유도 에너지선으로 공격한다. 다른 도시 이름을 먹으면 해당 도시의 PNG 라이벌 수호자가 소개 말풍선과 함께 상단에서 좌우 5회 왕복한 뒤 하강하며 가볍게 공격한다.

## 9. 디오라마 미제작 도시 배경

도시별 디오라마가 없는 목적지는 우주 성운 대신 기후별 공용 배경을 사용한다. 테마·가독성 규칙·배정 원칙은 `docs/15_fallback-scene-themes.md`가 SSOT다.
