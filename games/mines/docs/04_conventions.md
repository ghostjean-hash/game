# 04. 규약 (conventions)

이름 짓기, 주석, 테스트, 토큰 사용 규칙. 다른 문서와 겹치는 내용은 적지 않고 참조만 한다.

## 1. 이름 짓기

1.1. 파일명은 소문자 카멜(`boardView.js`), 폴더명은 소문자 한 단어(`core` / `render`).

1.2. 상수는 대문자 스네이크로 묶어 객체에 담는다(`CELL.min`, `TOUCH.longPressMs`). 낱개 상수를 흩어 두지 않는다.

1.3. 좌표는 `x`(가로) / `y`(세로)로 쓰고, 배열 색인 하나로 다룰 때는 `idx`로 쓴다. `row` / `col`은 쓰지 않는다 - 한 파일 안에서 두 체계가 섞이면 뒤바뀐 버그가 조용히 생긴다.

1.4. 칸 상태를 나타내는 값은 문자열이 아니라 `data/constants.js`의 상수를 쓴다.

## 2. 주석

2.1. 주석은 "무엇을 하는가"가 아니라 **"왜 이렇게 했는가"**를 적는다. 코드를 읽으면 알 수 있는 것은 적지 않는다.

2.2. 규격에서 온 결정에는 근거 위치를 남긴다(예: `// 첫 탭 안전 보장 - 01_spec.md 3.2`). 나중에 이 코드가 왜 이런지 되짚을 때 문서로 바로 갈 수 있어야 한다.

2.3. 되돌리기 지점이 있는 변경에는 되돌리는 방법을 한 줄 남긴다.

## 3. 수치와 색

3.1. 매직 넘버 0개. 모든 수치는 `src/data/constants.js`에서 온다. CSS 안의 수치도 토큰 변수로 뺀다.

3.2. 게임 데이터로서의 색(숫자 색, 칸 상태 색)은 `src/data/colors.js`. UI 색·간격·글꼴은 `styles/tokens.css` 변수. 인라인 색값 금지.

3.3. `02_data.md`를 고치지 않고 코드 수치만 바꾸는 것은 금지다. 문서가 먼저다.

## 4. 테스트

4.1. `core/`의 규칙을 바꾸면 같은 커밋에서 `tests/runner.js`를 함께 고친다.

4.2. 테스트는 브라우저에서 `tests/test.html`을 열어 돌린다. 외부 라이브러리를 쓰지 않는다.

4.3. 케이스 이름은 무엇이 보장되는지를 한국어 문장으로 적는다(예: `'첫 탭 칸과 이웃 여덟 칸에는 지뢰가 없다'`).

4.4. 플레이 흐름을 바꾸면 `tests/gameHarness.js`를 함께 고친다. 하네스는 화면 코드 없이도 시작·입력 의도·저장·종료를 재현할 수 있어야 한다.

## 5. 화면 문구

5.1. 시작 / 이어서 하기 / 계속하기 / 다시 하기 / 그만하기 / 환경설정은 공용 문구표(`shared/frame/text.js`)를 쓴다. 이 게임이 같은 뜻을 다르게 쓰지 않는다(표준 4.8-6).

5.2. 이 게임 고유 문구(모드 이름 등)는 `src/data/constants.js`에 모은다. 화면 코드에 문자열을 직접 쓰지 않는다.

5.3. 메뉴와 버튼에 부연 안내 문장을 붙이지 않는다. 설명이 필요하면 이름 자체를 고친다.
