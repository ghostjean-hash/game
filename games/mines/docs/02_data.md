# 02. 게임 데이터 (data)

모든 수치와 게임용 색의 정의. 코드의 매직 넘버는 0개이며, 아래 값은 전부 `src/data/constants.js`와 `src/data/colors.js`에 상수로 존재한다. 값을 바꿀 때는 이 문서를 먼저 고친다.

값을 그렇게 정한 근거는 기획서 `planning-mines.html`에 있다. 이 문서는 그 결정의 수치 실체다.

## 1. 난이도 (모바일 맞춤 3단, 2026-08-21 확정)

| 키 | 이름 | 가로 | 세로 | 칸 수 | 지뢰 | 지뢰 비율 |
|---|---|---|---|---|---|---|
| `easy` | 쉬움 | 9 | 9 | 81 | 10 | 12.3% |
| `normal` | 보통 | 12 | 12 | 144 | 25 | 17.4% |
| `hard` | 어려움 | 14 | 18 | 252 | 55 | 21.8% |

1.1. 세로 화면을 기준으로 가로 칸 수를 14 이하로 묶었다. 고전 원작의 고급 판(가로 30칸)은 세로 폰에서 칸 크기가 손가락 판정 하한 아래로 내려가 확대·이동 조작이 필수가 되므로 쓰지 않는다(`01_spec.md` 8.3).

1.2. 지뢰 비율을 12% → 17% → 22%로 올렸다. 원작 비율(12.3% / 15.6% / 20.6%)보다 중·상단을 조금 높인 값이다. 판이 작아진 만큼 추론 난도를 비율로 보전한다.

1.3. 기본 난이도는 `normal`이다. 처음 들어온 사용자에게도 이 값이 고른 상태로 표시되며, 마지막으로 고른 난이도가 저장돼 있으면 그것을 쓴다.

## 2. 칸 크기 산정

| 이름 | 값 | 뜻 |
|---|---|---|
| `CELL.min` | 24px | 칸 한 변의 하한. 이보다 작아지면 손가락으로 정확히 누를 수 없다 |
| `CELL.compactMin` | 20px | 낮은 가로 화면에서만 쓰는 하한. 하단 조작과 격자가 겹치는 것보다 작게라도 판 전체를 보이는 편이 낫다 |
| `CELL.max` | 48px | 칸 한 변의 상한. 넓은 화면에서 판이 과하게 커지지 않게 묶는다 |
| `CELL.gap` | 2px | 칸 사이 간격 |
| `BOARD.pad` | 12px | 격자 바깥 여백(좌우·상하 각각) |
| `BOARD.narrowPad` | 6px | 좁은 세로 화면에서만 쓰는 격자 바깥 좌우 여백 |
| `BOARD.narrowViewportWidth` | 386px | 어려움 판의 최소 폭(362px)과 기본 좌우 여백(24px)을 모두 담을 수 없는 기준 |
| `BOARD.uiTop` | 56px | 격자 위에 놓이는 UI 띠 높이 |
| `BOARD.uiBottom` | 104px + 하단 safe-area | 격자 아래 놓이는 모드 버튼 줄 높이. 홈 인디케이터 안전 영역을 함께 예약한다 |

2.1. 칸 크기는 가용 폭과 가용 높이를 둘 다 재서 작은 쪽에 맞춘다(표준 4.7-7). 가용 폭 = 뷰포트 폭 - 좌우 여백 - safe-area, 가용 높이 = 뷰포트 높이 - 위아래 UI - 여백 - safe-area.

2.2. 검산 - 아이폰 미니 세로(375×812) 어려움 판: 가용 폭 351px ÷ 가로 14칸 = 칸 약 25px로 하한 24px을 넘긴다. 가용 높이 약 636px ÷ 세로 18칸 = 35px이므로 폭이 병목이고, 최종 칸 크기는 25px이 된다.

2.3. 가로이면서 높이가 `BOARD.compactHeight` 이하인 화면에서는 `CELL.compactMin`을 쓴다. 이 경우 세로 18칸 판이 하단 모드와 겹치지 않고 한 화면에 남아야 한다.

2.4. 세로이면서 뷰포트 폭이 `BOARD.narrowViewportWidth`보다 작으면 좌우 여백을 `BOARD.narrowPad`로 줄인다. 어려움 판의 최소 격자 폭은 `14 × CELL.min + 13 × CELL.gap = 362px`이므로, 아이폰 12 mini의 375px 폭에서도 칸 크기 하한을 지키면서 양끝을 자르지 않는다.

2.5. 가로 방향에서는 세로 기준 폭 제한을 풀고 좌·우 UI 열을 같은 폭으로 맞춰 격자를 정중앙에 둔다(표준 4.7-5).

## 3. 조작 판정

| 이름 | 값 | 뜻 |
|---|---|---|
| `TOUCH.longPressMs` | 400ms | 길게 누르기 성립 시간 |
| `TOUCH.moveTolerance` | 10px | 이 거리를 넘겨 손가락이 움직이면 조작 취소 |
| `TOUCH.tapMaxMs` | 399ms | 짧게 탭으로 인정되는 상한(길게 누르기 성립 직전까지) |

3.1. 400ms는 일반 웹 관례인 500ms보다 짧다. 판 하나에 깃발을 수십 번 꽂는 게임이라 대기 시간이 곧 조작 피로가 되기 때문이다.

## 4. 색 (라이트 톤)

배경·UI 색은 `styles/tokens.css`의 디자인 토큰을 쓰고, 아래는 게임 데이터로서의 색이다(`src/data/colors.js`).

### 4.1. 숫자 색

인접 지뢰 수마다 색이 다르다. 고전 팔레트의 색 순서(파랑 → 초록 → 빨강 → …)를 계승하되, 라이트 배경에서도 충분히 읽히도록 대비를 맞춘 값이다.

| 숫자 | 색 | 원작 대응 |
|---|---|---|
| 1 | `#2563eb` | 파랑 |
| 2 | `#15803d` | 초록 |
| 3 | `#dc2626` | 빨강 |
| 4 | `#6d4cc7` | 남색(보라 계열로 구분) |
| 5 | `#b45309` | 갈색(주황 계열로 구분) |
| 6 | `#0e7490` | 청록 |
| 7 | `#334155` | 검정(짙은 슬레이트) |
| 8 | `#be185d` | 회색(분홍 계열로 구분) |

### 4.2. 칸 상태 색

| 상태 | 색 | 뜻 |
|---|---|---|
| `closed` | `#D9E2EE` | 닫힌 칸 |
| `closedAlt` | `#E4EAF3` | 닫힌 칸(체크무늬 교차) |
| `open` | `#F8FAFD` | 열린 칸 |
| `flag` | `#f5a524` | 깃발 |
| `mineHit` | `#e5484d` | 밟은 지뢰 |
| `mineShown` | `#AAB6C6` | 실패 후 공개된 나머지 지뢰 |
| `flagWrong` | `#F4C7C9` | 실패 후 드러난 잘못 꽂은 깃발 |
| `pressing` | `#B7C5D8` | 길게 누르기 판정이 성립한 칸 |

4.3. 닫힌 칸은 열린 칸보다 **밝다**. 둘의 밝기가 비슷하면 어디까지 열었는지 한눈에 보이지 않는다(원작이 회색 버튼과 흰 바탕으로 갈라 둔 것과 같은 이유). 닫힌 칸에는 위쪽에 얇은 흰 결 `inset 0 1px 0 rgba(255,255,255,.10)`을 둬 아직 눌리지 않은 것으로 보이게 하고, 열린 칸에는 그 결을 두지 않는다.

4.4. 닫힌 칸을 두 색 체크무늬로 깐다. 색 차이를 아주 작게 두어 무늬로 읽히지 않으면서도 칸 경계와 좌표 감각을 잡아 준다.

4.5. 허브 등록부에 쓰는 이 게임의 강조색(accent)은 `#f5a524`(호박색)이다. 깃발 색과 같으며, 기존 다섯 게임의 강조색과 겹치지 않는다.

## 6. 저장 키

네임스페이스는 `mines`이고, 실제 localStorage 키는 `gg.mines.*`가 된다(`shared/storage.js` 규칙).

| 키 | 내용 |
|---|---|
| `best` | 난이도별 최단 완료 시간(초). `{ easy, normal, hard }` |
| `lastDiff` | 마지막으로 고른 난이도 키 |
| `inprogress` | 진행 중인 판 상태(지뢰 배치, 열린 칸, 깃발, 경과 시간) |
| `muted` | 소리 끔 여부(공용 프레임이 관리) |

## 7. 시간 표시

7.1. 형식은 `분:초`이고 초는 두 자리로 채운다(예 `3:07`). 60분을 넘기면 그대로 분이 늘어난다.

7.2. 화면 갱신 주기는 1초다. 기록 비교에 쓰는 내부 값은 밀리초로 재고 표시할 때만 초로 내린다.
