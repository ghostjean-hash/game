# PROGRESS 아카이브 2026-09 - 실시간 기록에서 내용 그대로 옮긴 문단

## 59. 2026-09-04 · 게임 이동 구조 개편분 봉합 (이 창의 개발 작업 없음)

이 창은 코드를 만들지 않았다. 사용자 지시는 "AGENTS.md 파일까지 모두 커밋" 하나였고, 앞 창(codex)이 커밋하지 않고 남긴 변경 36건을 확인해 성격별로 나눠 커밋했다.

**무엇이 남아 있었나.** 게임 이동 구조 개편이다. 화면 위에 떠 있던 공용 나가기 버튼(`gg-hub-exit`)을 없애고, 허브로 돌아가는 길을 게임 홈 화면 안의 `<-` 하나(`gg-title-back`)로 통일했다. 프레임이 `mountHubBack`과 `frame.navigate.back()`을 내주고 게임은 스스로 주소를 바꾸지 않는다 - 나가는 문이 여러 개면 어느 문에서 무엇을 저장하는지 게임마다 달라지고, 실제로 과일 농장은 자기 HUD에서 직접 주소를 바꿔 나가고 있었다. 전체화면 버튼은 상단 띠에서 빠졌고 환경설정은 시작 화면의 추가 항목으로 자리를 옮겼다. 허브 첫 화면에 네 겹으로 쌓여 있던 인라인 스타일 275줄은 `shared/hub.css` 49줄로 분리됐다(허브 v2·v3·최종 라이트 테마가 서로를 덮어쓰던 층이 정리됐다). 커밋 셋으로 갈랐다 - 개편 본체(`e449883`), AGENTS.md 아홉 개(`5ab5efb`), 크롬 실행 바로가기(`29341f3`).

**빈 파일 두 개를 발견했다. 이것이 이번 봉합에서 가장 중요한 것이다.** `standards/html-game/STANDARD.md`가 0바이트였다. 직전 커밋 기준 245줄 20KB짜리 표준 본체이고, 이 폴더 게임 다섯이 모두 그 문서를 기준으로 만들어졌다. 지시대로 전부 커밋했으면 표준 본체가 저장소에서 통째로 사라졌을 것이다. 마지막 커밋본으로 되살린 뒤 커밋했다. 같은 시각(16시 35분)에 만들어진 `standards/html-game/plans/doc/platform-navigation.html`도 0바이트인데, 이쪽은 새 파일이라 되살릴 원본이 없다. 앞 창이 표준 본체 내용을 이 새 문서로 옮기다 중간에 끊긴 것으로 읽힌다 - 옮겨 담을 그릇을 만들고, 원본을 비우고, 채우기 전에 멈춘 모양새다. 프레임 코드 주석과 기획서 목차(`plans/nav.js`)는 이미 이 빈 문서를 기준 문서로 가리키고 있어, 지금 목차에서 그 항목을 누르면 백지가 뜬다.

**검증** - `tests/` 다섯 파일 145건 전부 통과(0 실패). 이동 구조 개편은 검사 항목 자체가 이번에 함께 바뀌었다(상단 띠 버튼 순서 검사가 빠지고, 허브 복귀가 홈 화면 `<-` 하나뿐인지 + 게임이 직접 주소를 바꾸지 않는지를 보는 검사가 들어왔다). 화면 실측은 하지 않았다 - 이 창은 커밋만 맡았다.

### 이번 cycle 자기 반성

- "모두 커밋"이라는 지시를 글자 그대로 따랐으면 표준 본체를 지웠다. 커밋 전에 바뀐 파일의 크기를 한 번 훑은 것이 유일한 안전망이었고, 그 훑기는 규칙이 아니라 우연에 가까웠다. 다른 도구가 남긴 작업분을 이어받아 커밋할 때는 "0바이트가 된 추적 파일이 있는가"를 먼저 보는 것이 기본 순서여야 한다.
- 빈 채로 커밋한 `platform-navigation.html`은 지금 목차에서 백지로 뜬다. 커밋하지 않고 두면 코드 주석이 없는 문서를 가리키고, 커밋하면 백지가 뜬다. 어느 쪽도 정상이 아니라 사용자 결정을 받아야 하는 자리로 남겼다.
