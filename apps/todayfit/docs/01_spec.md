# 01. 사양 (spec)

구현자가 읽는 규격. 화면·상태 전환·판정 규칙을 조건과 결과 형태로 적는다.

**무엇을 왜 그렇게 정했는가의 SSOT는 기획서 `planning-todayfit.html`이다.** 결정 근거·도면·뺀 항목과 그 이유는 그 문서에 있고, 여기에는 구현이 지킬 규격만 적는다. 둘이 어긋나면 기획서가 진실이다. 수치는 전부 `02_data.md`가 SSOT이며 여기서는 이름으로만 부른다.

## 1. 한 줄

월 단위로 짜 둔 운동 계획을 그날 실행하고, 계획 대비 실제 수행 결과를 남기는 개인 전용 앱이다.

## 2. 화면

2.1. 주 화면 셋을 하단 이동 막대로 오간다 - 오늘 `S-01` · 달력 `S-02` · 설정 `S-03`.

2.2. 관리 화면 여덟은 주 화면에서 들어간다 - 날짜 상세 `S-04` · 날짜별 계획 수정 `S-05` · 요일 규칙 `S-06` · 루틴 목록 `S-07` · 루틴 편집 `S-08` · 운동 템플릿 목록 `S-09` · 운동 템플릿 편집 `S-10` · 기본값과 소리 `S-11`.

2.3. 실행 화면 둘은 이동 막대를 감춘다 - 운동 실행 `S-12` · 운동 종료 요약 `S-13`.

2.4. 앱 진입 지점은 오늘 화면이다. 진행 중 세션이 있으면 오늘 화면의 다른 표시보다 앞에 이어하기 안내를 둔다.

2.5. **운동 실행 진입점은 오늘 화면 하나다.** 달력과 날짜 상세에서는 실행에 들어가지 않는다.

2.6. 실행 화면에서는 이동 막대와 뒤로 가기를 막는다. 마지막 세트 완료 또는 운동 종료 확인을 거쳐 종료 요약으로만 빠져나온다. 종료 요약 닫기는 오늘 화면으로 간다.

2.7. 오늘 화면은 아래 다섯 상태 가운데 하나를 표시한다. 위에서부터 먼저 맞는 것을 쓴다.

| 순위 | 상태 | 조건 |
|---|---|---|
| 1 | 이어하기 | 진행 중 세션 존재 |
| 2 | 남은 운동 계속 | 오늘 기록이 `partial`이고 재개 대상 세트 잔여 |
| 3 | 완료 | 오늘 기록이 `complete` |
| 4 | 시작 대기 | 오늘 계획 존재, 기록 없음 |
| 5 | 계획 없음 | 오늘 계획 없음 |

2.8. 오늘 기록이 `partial`인데 재개 대상 세트가 0개면(건너뛴 운동만 남은 경우) 3번과 같은 결과 요약만 표시하고 재개 조작을 내지 않는다.

## 3. 계층과 계획 생성

3.1. 데이터는 다섯 계층이다 - 운동 템플릿 → 루틴 → 요일 규칙 → 날짜별 계획 → 수행 기록.

3.2. 앞 세 계층은 참조로 잇는다. 상위를 고치면 하위에 즉시 반영된다.

3.3. **요일 규칙에서 날짜별 계획으로 넘어갈 때 값을 복사하고 참조를 끊는다.** 월간 계획 생성 이후 요일 규칙·루틴·운동 템플릿·앱 기본값을 고쳐도 이미 생성된 날짜별 계획은 바뀌지 않는다.

3.4. **날짜별 계획에서 수행 기록으로 넘어갈 때도 값을 복사한다.** 운동 시작 시점의 계획 전체를 스냅샷으로 갖는다. 이후 계획을 고쳐도 지나간 기록은 바뀌지 않는다.

3.5. 값 적용 순서는 아래와 같다. 월간 계획 생성 시점에 확정값 하나로 눌러 담는다.

| 값 | 1순위 | 2순위 | 3순위 |
|---|---|---|---|
| 세트 수 | 루틴 지정값 | 운동 템플릿 기본값 | - |
| 반복 횟수 | 루틴 지정값 | 운동 템플릿 기본값 | - |
| 세트당 권장 수행시간 | 루틴 지정값 | 운동 템플릿 기본값 | 앱 기본값 |
| 세트 간 휴식시간 | 루틴 지정값 | 운동 템플릿 기본값 | 앱 기본값 |

3.6. 시작 전 준비시간과 운동 간 전환시간은 날짜별 계획에 담지 않는다. 운동 시작 시점의 앱 설정값을 읽는다.

3.7. 월간 계획 생성 절차.

1. 요일 규칙에서 `enabled`인 요일을 뽑는다.
2. 그 달의 생성 대상 기간(3.7.1)에서 해당 요일에 드는 날짜를 뽑는다.
3. 그 가운데 이미 계획이 있는 날짜는 건너뛴다(3.7.2).
4. 날짜마다 연결 루틴의 운동 항목을 순서대로 편다.
5. 각 운동의 네 수치를 3.5 순서로 확정한다.
6. 생성 일수와 날짜별 루틴 이름을 미리보기로 보인다.
7. 확정 시 날짜별 계획을 일괄 저장한다.

3.7.1. **생성 대상 기간에 지난 날짜를 담지 않는다** (사용자 결정 2026-09-18).

| 보고 있는 달 | 생성 대상 기간 | 생성 조작 |
|---|---|---|
| 이번 달 | 오늘부터 월말까지. 오늘은 담고 오늘 이전 날짜는 담지 않는다 | 낸다 |
| 다음 달 이후 | 그 달 전체 | 낸다 |
| 지난 달 | 없음 | 내지 않는다 |

앱을 쓰기 시작하기 전 날짜에 계획을 만들면 그 날짜는 곧바로 미실시가 된다. 쓰지도 않던 기간이 실패 기록으로 쌓이면 달성률이 "앱을 쓰기 시작한 뒤 계획을 얼마나 지켰는가"를 나타내지 못한다. 9월 18일에 9월 계획을 만들면 9월 18일부터 30일 사이의 해당 요일만 생기고 9월 1일부터 17일은 계획 없음으로 남는다.

3.7.2. **이미 계획이 있는 날짜는 덮어쓰지 않는다** (사용자 결정 2026-09-18). 생성 대상 기간 안에서 계획이 없는 날짜만 채운다. 저장에 자동 생성분과 손으로 고친 계획을 가르는 표식이 없어, 있는 날짜를 다시 만들면 고쳐 둔 계획이 조용히 덮인다.

3.8. 날짜당 계획은 하나다. 같은 날짜에 계획을 둘 만들지 않는다.

3.9. 날짜별 수정은 오늘 이후의 계획일 가운데 수행 기록이 없는 날짜만 받는다. 지난 날짜와 기록이 있는 날짜는 잠근다.

3.9.1. **진행 중 세션이 귀속된 날짜도 잠근다.** 그 날짜는 아직 수행 기록이 없지만 운동이 돌고 있고, 계획을 지우면 끝난 뒤 저장되는 기록이 계획 없는 날에 놓여 달력과 달성률에서 통째로 사라진다(2026-09-18 검사 적발).

3.10. 날짜별 계획 삭제는 그 날짜를 `none`으로 만든다. 그 날짜는 미실시 집계에서도 빠진다.

## 4. 운동 실행

### 4.1. 구간

구간은 넷이다 - `prep` · `work` · `rest` · `transition`. 세션 상태는 셋이다 - `running` · `paused` · `ended`.

4.1.1. `prep` · `rest` · `transition`은 정해진 시간이 지나면 자동으로 다음 구간으로 간다.

4.1.2. **`work`는 자동으로 끝나지 않는다.** 권장 수행시간이 지나도 구간을 유지하고 초과 시간을 계속 센다. 세트 완료는 다음 버튼으로만 확정한다. 자동 종료도 자동 일시정지도 하지 않는다.

4.1.3. 마지막 운동 뒤에는 `transition`을 두지 않는다. 바로 종료로 간다.

### 4.2. 전환표

| 현재 | 사건 | 조건 | 다음 | 기록 |
|---|---|---|---|---|
| `prep` | 시간 만료 · 다음 짧게 | - | `work` (1번 운동 1세트) | - |
| `work` | 권장 수행시간 만료 | - | `work` 유지, 초과 계측 시작 | - |
| `work` | 권장 수행시간 + 재안내 지점 경과 | - | `work` 유지 | - |
| `work` | 다음 짧게 | 마지막 세트 아님 | `rest` | 현재 세트 완료 |
| `work` | 다음 짧게 | 마지막 세트, 마지막 운동 아님 | `transition` | 세트 완료 + 운동 완료 |
| `work` | 다음 짧게 | 마지막 세트, 마지막 운동 | 종료 | 세트 완료 + 전체 상태 판정 |
| `rest` | 시간 만료 · 다음 짧게 | - | `work` (같은 운동 다음 세트) | - |
| `transition` | 시간 만료 · 다음 짧게 | - | `work` (다음 운동 1세트) | - |
| `work` `rest` `transition` | 다음 길게 | 마지막 운동 아님 | `transition` | 현재 운동 건너뜀, 잔여 세트 미완료 |
| `work` `rest` `transition` | 다음 길게 | 마지막 운동 | 종료 | 현재 운동 건너뜀, 전체 상태 `partial` |
| 모든 구간 | 일시정지 | - | 구간 유지, 타이머 정지 | - |
| `paused` | 계속 | - | 직전 구간 재개 | - |
| 모든 구간 | 운동 종료 확인 | - | 종료 | 잔여 세트·운동 전부 미완료, 전체 상태 `partial` |
| 모든 구간 | 앱 중단 | - | 중단 지점 보존 | 4.5 참조 |

4.2.1. **전환 구간의 길게 누름은 지금 막아 두었다(구현 보류, 기획 결정 대기).** 위 표는 `work` · `rest` · `transition` 셋에서 길게 누름이 `현재 운동`을 건너뛴다고 정했는데, 전환 구간의 `현재 운동`은 이미 결과가 확정된 직전 운동이다. 그대로 두면 화면 가운데에 다음 운동이 떠 있는 상태에서 길게 눌렀을 때 **다 마친 앞 운동이 건너뜀으로 강등되고 그날 전체가 `complete`에서 `partial`로 떨어진다.** 기록이 깨지는 쪽이라 화면에서 길게 누름을 받지 않도록 막았고, 다음 운동을 대상으로 삼을지 전환 구간에서는 아예 두지 않을지는 사용자 결정으로 남긴다(2026-09-17).

### 4.3. 다음 버튼

4.3.1. 짧게 누름은 구간마다 역할이 갈린다. `work`에서는 세트 완료 확정, 나머지 셋에서는 잔여 시간 생략이다.

4.3.2. 길게 누름(`LONG_PRESS_MS` 이상)은 현재 운동 전체 건너뛰기다. 완료 세트는 유지하고 잔여 세트를 미완료로, 그 운동을 `skipped`로 남긴다.

4.3.3. 건너뛰기에 확인 창을 두지 않는다. 대신 `UNDO_WINDOW_SECONDS` 동안 되돌리기를 노출한다.

4.3.4. 되돌리기는 건너뛰기 직전의 구간·잔여 시간·완료 세트 수를 그대로 되살린다. **되돌리기 대기 동안 다음 구간 타이머를 정지한다.**

4.3.5. 되돌리기 시간이 지나거나 되돌리기 외 조작이 들어오면 건너뛰기를 확정한다.

### 4.4. 일시정지

4.4.1. 네 구간의 타이머와 소리를 모두 멈춘다.

4.4.2. 일시정지 시간은 `activeSeconds`에 더하지 않는다.

4.4.3. 계속을 누르면 정지 시점의 잔여 시간(또는 초과 시간)부터 이어간다.

### 4.5. 앱 중단과 복구

4.5.1. 앱·브라우저가 예기치 않게 닫힌 경우를 자동 일시정지와 같게 처리한다. 닫혀 있던 동안 구간을 진행시키지 않는다.

4.5.2. 복구 후 상태는 중단 시점의 구간에 따라 갈린다.

| 중단 시점 | 복구 후 | 완료 세트 |
|---|---|---|
| `prep` | `prep` 처음부터, 정지 상태 | - |
| `work` | 그 세트 처음부터, 정지 상태 | 유지 |
| `rest` | 중단 시점 잔여 시간 그대로, 정지 상태 | 유지 |
| `transition` | 중단 시점 잔여 시간 그대로, 정지 상태 | 유지 |

4.5.3. 닫혀 있던 시간은 `activeSeconds`에 더하지 않는다. 끊긴 구간의 진행분도 더하지 않는다 - 그 구간을 다시 하므로 그때 다시 센다.

4.5.4. 복구 진입은 오늘 화면의 이어하기다. 진입하면 정지 상태에서 재개를 기다린다.

4.5.5. 휴식·전환의 남은 시간을 살리려면 앱이 살아 있던 마지막 시점을 알아야 한다. 화면이 숨거나 페이지가 내려갈 때 그 시점의 구간 경과를 적어 둔다.

- 그 표식이 있으면 4.5.2의 휴식·전환은 적힌 남은 시간부터 이어간다
- 표식 없이 끊긴 경우(전원이 나가는 식의 딱딱한 중단)에는 그 구간도 처음부터 간다. 쉬는 시간을 더 주는 쪽이라 안전한 쪽으로 틀어진다
- 이 표식은 복구에만 쓴다. 살아 있는 세션의 시간 계산에는 관여하지 않는다

### 4.6. 같은 날 재개

4.6.1. `partial`로 끝난 날은 같은 달력 날짜 안에서 남은 운동을 이어서 할 수 있다. 진입은 오늘 화면의 `남은 운동 계속`이다.

4.6.2. 재개 대상은 **건너뛰지 않은 운동의 미완료 세트**다. 완료한 세트와 `skipped` 운동은 대상 밖이다.

4.6.3. 새 기록을 만들지 않고 그 날짜의 기록을 다시 진행 중 세션으로 연다. `startedAt`은 유지하고, `endedAt`은 재개 세션 종료 시점으로 갱신하며, `activeSeconds`는 누적한다.

4.6.4. 세션과 세션 사이의 중단 기간은 `activeSeconds`에 더하지 않는다.

4.6.5. 재개 시 `prep` 구간을 첫 시작과 같게 한 번 진행한다.

4.6.6. 재개 횟수에 제한을 두지 않는다. 자정이 지나면 그 날짜는 과거가 되어 재개 대상에서 빠진다.

4.6.7. 재개 종료 시점에 5.2 기준으로 전체 상태를 다시 판정한다. 남은 세트를 모두 채우고 `skipped`가 없으면 `complete`로 바뀐다.

## 5. 날짜 상태

5.1. 판정표. 저장하는 것은 계획의 존재 여부와 기록의 `status`뿐이고, 나머지는 조회 시점에 계산한다.

| 계획 | 기록 | 날짜 | 상태 |
|---|---|---|---|
| 없음 | - | - | `none` |
| 있음 | 없음 | 오늘 또는 미래 | `planned` |
| 있음 | 없음 | 과거 | `missed` |
| 있음 | `complete` | - | `complete` |
| 있음 | `partial` | - | `partial` |
| 있음 | 진행 중 세션 귀속 | - | `planned` + 진행 중 표기 |

5.2. `complete` 조건은 계획된 모든 운동의 모든 세트 완료다. `skipped` 0개, 미완료 세트 0개여야 한다.

5.3. `partial`은 운동을 시작했으나 5.2를 채우지 못한 경우다. 완료 세트 0개도 여기 든다.

5.4. `missed`와 `partial`을 가르는 것은 수행 기록의 존재 여부 하나다. 기록은 운동 시작 조작이 만든다.

5.5. 하루 경계는 로컬 달력 날짜다. 수행 기록은 운동 시작 시점의 날짜에 귀속한다.

5.6. 자정 시점에 진행 중 세션이 있으면 시작한 날짜에 계속 귀속하고 그 날짜를 `missed`로 바꾸지 않는다.

| 시작 | 종료 | 귀속 | 시작 날짜 계획 |
|---|---|---|---|
| 화 22:00 | 화 23:10 | 화요일 | `complete` 또는 `partial` |
| 화 23:55 | 수 00:20 | 화요일 | `complete` 또는 `partial` |
| 수 00:05 (당일 첫 시작) | - | 수요일 | 화요일은 `missed` |

5.7. 계획이 없는 날짜에는 운동을 시작할 수 없다.

5.8. 예정 시간은 표시 전용이다. 계획일 안에서는 어느 시각에나 시작할 수 있다.

## 6. 계산

6.1. 예상 총 운동시간.

```
T = P + Σ( Wi × Si + Ri × (Si − 1) ) + C × (N − 1)
```

`P` 시작 전 준비시간, `Wi` 운동 i의 세트당 권장 수행시간, `Si` 세트 수, `Ri` 세트 간 휴식시간, `C` 운동 간 전환시간, `N` 그날 운동 수. 단위는 초, 화면 표기는 분 단위 반올림이다.

6.2. 마지막 운동 뒤에는 전환이 없으므로 전환 항의 계수가 `N − 1`이다.

6.3. 예상값이므로 실제 `activeSeconds`와 다르다. 운동 구간이 사용자 조작으로 끝나기 때문에 차이가 늘 생긴다.

6.4. 달성률과 진행. 주간과 월간에 같은 식을 각각 적용한다.

```
달성률 = 그 기간의 완료 일수 ÷ 그 기간의 도래 계획 일수
진행   = 그 기간의 완료 일수 / 그 기간의 계획일 전체
```

6.5. 도래 계획 일수는 그 기간의 계획일 가운데 결과가 확정된 날짜 수다. `complete` · `partial` · `missed` 셋이 분모에 들고, 앞으로 남은 `planned`는 빠진다.

6.6. 완료 일수는 `complete`인 날짜만 센다. `partial`은 분자에 들지 않는다.

6.7. 도래 계획 일수가 0이면 달성률 자리에 해당 없음을 표시한다.

6.8. 주의 경계는 월요일 시작, 일요일 종료다. 주간 달성률과 주간 진행에 같은 경계를 쓴다.

## 7. 소리

7.1. 시점과 내용.

| 시점 | 음성 | 비프 |
|---|---|---|
| `prep` 시작 | 준비 + 첫 운동명 + 1세트 | - |
| `prep` 마지막 3초 | 카운트다운 | 3회 |
| 세트 시작 | 운동명 + 세트 번호 | - |
| 마지막 세트 시작 | 운동명 + 마지막 세트 | - |
| 권장 수행시간 경과 | 경과 안내 | 1회 |
| 권장 수행시간 + 재안내 지점 | 경과 재안내 | 1회 |
| 세트 완료 확정 | 세트 완료 | 1회 |
| `rest` 시작 | 휴식 + 휴식시간 | - |
| `rest` 마지막 3초 | 카운트다운 | 3회 |
| `transition` 시작 | 다음 운동 + 다음 운동명 | - |
| `transition` 마지막 3초 | 카운트다운 | 3회 |
| 운동 건너뛰기 | 건너뛰기 + 다음 운동명 | 1회 |
| 전체 종료 | 운동 완료 | 긴 1회 |

7.2. 초과 안내는 위 두 번으로 끝난다. 다음 버튼을 누를 때까지 되풀이하지 않는다.

7.3. `transition` 종료 5초 전 재안내를 두지 않는다. 전환 종료 직후의 세트 시작 안내가 같은 운동명을 다시 부르기 때문이다.

7.4. 음성과 비프는 각각 따로 끈다. 둘 다 꺼도 구간 진행 규칙은 달라지지 않는다.

7.5. 일시정지 중에는 소리를 내지 않는다. 계속을 누르면 그 구간의 남은 안내만 이어서 낸다.
