# 04. 규약 (conventions)

이름 짓기, 주석, 테스트, 토큰 사용 규칙. 구조는 `03_architecture.md`, 수치는 `02_data.md`가 SSOT다.

## 1. 이름

1.1. 파일은 카멜 케이스(`dayStatus.js`), 폴더는 소문자 한 낱말(`core` · `render` · `store` · `platform`).

1.2. 코드 안 이름은 영어, 화면에 나가는 글자는 한국어다. 화면 문구를 코드에 직접 적지 않고 `src/data/phrases.js`에서 가져온다.

1.2.1. `index.html`에는 화면에 뜨는 글자를 적지 않는다. 같은 낱말이 두 곳에 있으면 고치는 쪽을 틀리게 고른다. 상단 띠 제목과 이동 막대 글자는 빈 채로 두고 `main.js`가 문구표에서 채운다.

1.2.2. 예외는 **자바스크립트가 뜨기 전이나 앱 바깥에서 읽히는 값**이다.

- `<title>` · `app.webmanifest`의 이름 · `apple-mobile-web-app-title` - 홈 화면에 추가하는 시점과 탭 목록에서 읽히므로 정적 값이어야 한다. `<title>`은 문서가 뜬 뒤 `main.js`가 문구표 값으로 다시 맞춘다
- `aria-label` - 눈에 보이는 글자가 아니라 화면 낭독기가 읽는 이름이다. 자바스크립트가 채우면 그것이 늦게 뜨는 동안 이름 없는 버튼이 되므로 `index.html`에 정적으로 적는다. 보이는 글자와 사본 관계가 아니라 1.2.1의 문제도 생기지 않는다

1.3. 도메인 이름을 기획서와 일치시킨다. 옮겨 쓰는 짝은 아래로 고정한다.

| 기획서 | 코드 |
|---|---|
| 운동 템플릿 | `exercise` |
| 루틴 | `routine` |
| 루틴 항목 | `routineItem` |
| 루틴 지정값 | `routineItem`의 `sets` · `reps` · `workSeconds` · `restSeconds` |
| 요일 규칙 | `weeklyRule` |
| 날짜별 계획 | `dayPlan` |
| 수행 기록 | `session` |
| 진행 중 세션 | `activeSession` |
| 구간 | `phase` |
| 세트당 권장 수행시간 | `workSeconds` |
| 세트 간 휴식시간 | `restSeconds` |
| 운동 간 전환시간 | `transitionSeconds` |
| 시작 전 준비시간 | `prepSeconds` |

1.4. 시간 값 이름에는 단위를 붙인다 - 초는 `...Seconds`, 밀리초는 `...Ms`, 시각은 `...At`. 단위 없는 시간 이름을 만들지 않는다.

1.5. 세트 번호는 1부터 센다(`setNumber`). 배열 자리 번호는 0부터 센다(`exerciseIndex`). 이름을 달리해 둘을 섞지 않는다.

1.6. 날짜 키는 `date`, 요일은 `weekday`다. 요일은 월요일 1부터 일요일 7까지다.

## 2. 수치

2.1. **매직 넘버 0개.** 코드에 숫자 리터럴을 적지 않고 `src/data/constants.js`에서 가져온다.

2.2. 예외는 0과 1, 그리고 배열 자리 계산의 자명한 값뿐이다.

2.3. 값을 바꿀 때는 `02_data.md`를 먼저 고치고 `constants.js`를 맞춘다. 반대로 하지 않는다.

## 3. 시간

3.1. 경과 시간은 항상 시각 차이로 구한다. 틱을 세어 더하지 않는다. 화면이 숨으면 틱이 늘어져 값이 어긋난다.

3.2. 지금 시각을 읽는 자리는 `platform/ticker.js` 하나다. `core/`는 시각을 인자로 받는다.

3.3. 날짜 비교는 날짜 키 문자열끼리 한다. `Date` 객체를 비교하지 않는다 - 시·분이 섞여 같은 날이 다른 날로 갈린다.

3.4. 시간대 변환을 하지 않는다. 로컬 달력 날짜가 기준이다.

## 4. 저장

4.1. `localStorage`를 직접 부르지 않는다. `src/store/repo.js`만 저장에 손대고, 그 안에서 `createStorage("todayfit")`를 쓴다.

4.2. 저장 구조를 바꾸면 `02_data.md` 5장을 고치고 판 번호를 올리며 올림 처리를 둔다.

4.3. 읽을 때 값이 없거나 깨져 있으면 기본값으로 시작한다. 깨진 값 때문에 화면이 뜨지 않는 상태를 만들지 않는다.

## 5. 색과 스타일

5.1. 색·간격·글자 크기는 토큰 변수만 쓴다. 인라인 값 금지.

5.2. 이 앱은 밝은 바탕이다. `styles/tokens.css`가 `:root`에서 공용 토큰 값을 덮어쓰고, **토큰 이름은 바꾸지 않는다.** 이름을 바꾸면 `shared/base.css`의 공통 버튼과 팝업이 색을 잃는다.

5.2.1. 밝은 톤을 위해 새 이름을 만들지 않는다. 화면 코드에 `--bg-light` 같은 이름이 등장하면 잘못된 것이다.

5.2.2. 이 앱만 쓰는 값(날짜 상태 넷)은 `styles/tokens.css`에 새로 정의한다. 공용 파일은 고치지 않는다.

5.3. 상태를 색으로만 구분하지 않는다. 달력의 네 상태는 색과 함께 모양으로도 갈린다.

5.4. 운동 실행 화면의 버튼은 `--touch-min` 이상이다. 땀 묻은 손으로 누르는 자리라 다른 화면보다 크게 잡는다.

## 6. 주석

6.1. 무엇을 하는지는 적지 않는다. 코드가 말한다.

6.2. **왜 그렇게 했는지만 적는다.** 특히 브라우저 사정 때문에 모양이 비틀린 자리에는 반드시 남긴다 - 그 자리가 나중에 다른 바탕으로 옮길 때 걷어낼 자리다.

6.3. 기획서나 사양의 조항을 가리킬 때는 문서 이름과 절 번호를 함께 적는다(`01_spec.md 4.6.2`).

## 7. 테스트

7.1. `core/`를 고치면 같은 판에서 테스트도 고친다.

7.2. 실행은 `node tests/run-node.js`(작업 폴더 `apps/todayfit`)다.

7.3. 새 규칙을 넣을 때는 규칙을 깨는 경우를 먼저 적는다. 모서리부터 적는다 - 세트 1개, 운동 1개, 자정 통과, 건너뜀만 남은 날.

7.4. `03_architecture.md` 6.2의 목록을 줄이지 않는다. 항목을 지우려면 그 문서를 먼저 고친다.

## 8. 화면

8.1. `render/`는 상태를 읽어 그리기만 한다. 상태를 바꾸지 않는다.

8.2. 화면 갱신은 필요한 자리만 손댄다. 운동 실행 화면은 1초에 네 번 갱신되므로 매번 전체를 다시 그리지 않는다.

8.3. 브라우저 기본 동작을 막는 자리(맥락 메뉴·글자 선택)는 `input/pressInput.js`와 공용 CSS에 모으고 화면 코드에 흩지 않는다.

## 9. 문서

9.1. 코드를 고치기 전에 영향받는 문서를 먼저 고친다. 문서와 코드가 어긋나면 문서가 진실이다.

9.2. 결정을 바꾸려면 기획서 `planning-todayfit.html`부터 고친다. 사양·데이터·구조 문서는 그 결정을 따라 움직인다.

9.3. 기획서를 고쳤으면 용어·표기 검사를 돌린다.

```
node ~/.claude/skills/planning-language/check-planning-language.js apps/todayfit/docs/planning-todayfit.html
```
