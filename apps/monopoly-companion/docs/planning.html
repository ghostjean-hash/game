  3. 부지 창: 왼쪽 실물 권리증(색 띠 · 소유자 띠 · 임대료 표 · 가격 · 건물 한 채 · 저당), 지금 받는 임대료 줄만 바탕 강조. 오른쪽은 독점 묶음(같은 색 부지 단추) · 집 짓기 · 팔기/저당 · 기록 맞추기. 이름은 권리증 띠에 한 번만, 독점 효과 설명 문장과 작은 회색 안내는 지운다(효과는 임대료 표와 메뉴 → 규칙에 있다). 닫기 단추는 오른쪽 위 모서리, 아래 줄은 "돌아가기"(+ 건설).
  4. 집 짓기: 독점이 완성된 도시를 누르면 그 부지 창 안에서 바로 "모두 1채 … 모두 호텔"과 도시별 −/수량/+ · 건설 뒤 임대료 · 건축비 · 남는 현금을 보이고, 아래 "건설 M금액"으로 끝낸다. 누른 도시 줄은 굵은 테두리. 집 짓기 아이콘은 지을 수 있는 색이 하나뿐이면 색 고르기를 건너뛰고 바로 계획으로 간다. 계획 본문은 여러 채 짓기 창과 같은 부품(constructionBody)을 쓴다. 균등 건설 위반 같은 막힘 이유는 계획을 바꿨을 때만 그 줄에 보인다(자리는 미리 잡아 흔들림 0).

0.25. 앱 화면 UI/UX 표준 적용 재설계 (2026-11-22)

0.25.1. 왜

사용자 지시 "모노폴리 ui/ux를 표준 규격에 맞게 재설계 및 업그레이드". 기준은 글로벌 「앱 화면 UI/UX 표준」(~/.claude/standards/app-ui-ux-standard.md) 전 절과 부록 A(게임 화면)다(사용자 승인). 걸린 지시 1~11절이 표준보다 앞선다. 0.23 "상용 수준"이 색 · 그림자 덧칠에 그쳐 사용자가 만족하지 않았으므로(표준 7.8 "색만 바꾸지 말고 구조 · 배치까지"), 이번에는 진행 칸의 구조를 바꾸고 시안을 먼저 보인다.

0.25.2. 지금 화면에서 표준에 걸리는 것 (1180×820 · 1366×1024 캡처로 확인)

  1. 진행 칸에 지금 차례 한 사람의 현금만 보이고 상대 현금 · 위치가 없다 - 다음 판단에 필요한 상태는 늘 보인다(3.10).
  2. 처리 내용(주사위 · 구입 질문 · 내야 할 돈)이 칸 가운데 떠 있어 장면마다 주 단추 높이가 다르다 - 같은 역할 요소는 같은 자리(2.5), 주 조작은 우하단에 크게(A.2).
  3. 구입 · 임대료 처리에 대상 부지가 글자로만 나온다 - 핵심 대상은 실물 모양 그림으로(7.6 · 7.9). 구입 금액이 질문 아래와 단추에 두 번 나올 여지 - 같은 값은 한 번(4.5).
  4. 보드 가운데 그러데이션(0.23에서 넣음), "플레이 시간" 이름표, 주사위 위 "첫 번째 · 두 번째" 작은 글자 - 장식 · 자리로 드러나는 값의 이름표 금지(4.1 · 4.7).
  5. 준비 화면 아래 4분의 1이 빈 자리이고 두 사람 칸 가운데가 비어 있다 - 아무것도 가르지 않는 빈 여백은 걷는다(3.11). 시안 다음 판에서 다룬다.

0.25.3. 시안 (진행 화면 오른쪽 칸)

  1. 맨 위 두 사람 칸: 아빠 · 서우를 같은 크기 두 칸으로 나란히. 칸마다 색 점 · 이름 · 현금(큰 글자) · 지금 위치. 지금 차례 칸은 플레이어 색 3px 테두리와 옅은 플레이어 색 바탕(8.4 색 · 두께 둘 다 다르게). 걸린 지시 9절의 "차례 · 위치 · 잔액 오른쪽 칸 맨 위"를 두 사람으로 넓힌 것이다.
  2. 처리 칸: 대상(권리증 · 낼 돈)은 칸 가운데, 주 단추는 칸 맨 아래 같은 자리 · 같은 높이(64px) · 칸 폭 전체. 구입은 "구입 M금액 / 경매" 두 단추, 질문 문장과 따로 쓴 금액은 지운다.
  3. 권리증 그림: 색 띠(그 도시 색 묶음) + 도시 이름 + 기본 임대료. 임대료 처리 때는 소유자 색 띠를 덧대고 임대료 줄 대신 "아빠에게 M금액"을 크게.
  4. 주사위: 시안(글자 삭제 · 2열 3줄 확대)은 사용자가 "주사위는 지금이 낫다"로 물렸다. 선택판 모양(글자 · 3열 2줄 · 면 크기 · 두 판 간격)은 그대로 두고, 이동 단추만 다른 주 단추와 같은 자리 · 폭 · 높이로 맞춘다(걸린 지시 12절).
  5. 시계: "플레이 시간" 이름표 삭제, 멈춤은 시계 옆 일시정지 기호로. 보드 가운데는 단색.

0.25.4. 시안 확인 방법

저장소를 고치지 않고, 개발 서버의 실제 앱 위에 덧씌우기(모양 · 구조)를 얹어 같은 저장 상태를 지금판 · 시안판으로 찍었다. 네 장면 × 두 크기(1366×1024 · 1024×680) 화면 넘침 0. 사용자 답 "주사위는 지금이 낫고, 나머지는 시안이 좋아"(2026-11-22)로 확정.

0.25.5. 반영 (설계)

  1. app.js: 진행 칸 머리를 playerCards(두 사람 칸)로 바꾼다. 처리 대상은 deedCard(권리증 그림) · dueView(누구에게 · 금액) · 카드 그림(그 칸 그림 + 이름)으로 그린다. 구입 단추는 "구입 M금액 / 경매", 현금이 모자라면 "M금액 중 M부족액 부족" 한 줄과 돈 마련 단추. 부지 정보 창은 제목 줄을 그 부지의 색 띠로 그리고, 강조된 임대료 칸과 겹치는 "현재 임대료" 줄을 지운다(4.5). 일시정지 상태(오토 꺼짐)에서 진행 칸에 is-paused를 달아 시계 옆 멈춤 기호를 보인다.

  1. 사용자 지적: 스탠다드 · 공식 단축 탭을 누르면 칸 크기가 바뀌고 게임 시작 단추가 오르내린다. 두 번째 받는 현금 단추 안 선물 아이콘이 가운데가 아니다.

  3. 규칙: 탭·선택지를 바꿔도 어떤 상자의 크기와 위치도 변하지 않는다. 모드마다 있고 없는 줄은 없는 모드에서도 같은 자리를 보이지 않게 잡아 둔다(화면·읽기 프로그램 모두 안 보임). 아이콘 단추의 그림은 단추 한가운데에 둔다(허용 0.6px).

0.23. 상용 수준 마감 - 색 · 깊이 · 글자 위계 · 누름 반응 · 창 움직임 (2026-11-21)

0.23.1. 왜

사용자 지시 "ui/ux를 상용 서비스 수준으로". 0.22로 배치·크기 규칙은 맞췄지만 화면 마감이 시제품 수준이다. 독점 배경이 회색이 섞여 탁하고, 보드 가운데가 평평한 빈 면이며, 진행 칸 질문 글자가 가늘어 위계가 약하고, 창이 툭 나타나며, 단추를 눌러도 손맛이 거의 없다. 사용자 부재 중 무질문 완주 지시라 배치·문구 결정은 걸린 지시 범위 안에서만 한다.

0.23.2. 이번에 고칠 것

  1. 색: 독점 배경은 회색이 섞이지 않은 맑은 플레이어 색으로 바꾼다. 독점이 아닌 소유 칸보다 진한 단계는 유지한다(걸린 지시 6절). 보드 가운데는 가장자리가 살짝 어두운 은은한 면 처리로 실물 판 느낌을 준다. 글자·그림·로고는 넣지 않는다.
  2. 깊이: 오른쪽 칸 상자·보드 테두리·팝업에 같은 두 단계 그림자를 쓴다. 상자는 낮은 그림자, 팝업은 높은 그림자.
  3. 글자 위계: 진행 칸 질문 문장은 굵고 진하게, 금액 숫자는 자릿수가 흔들리지 않는 숫자 모양으로 통일한다.
  4. 누름 반응: 모든 단추는 누르는 동안 살짝 작아졌다 돌아온다(120ms). 주사위 면은 고를 때 한 번 튀어 오른다. 이동 단추는 두 면이 모두 골라지면 부드럽게 켜진다.
  5. 창 움직임: 팝업은 열릴 때 살짝 아래에서 떠오르며 나타나고(200ms) 뒤 배경은 서서히 어두워진다. 반복 움직임은 넣지 않는다. 기기에서 움직임 줄이기를 켜면 모두 끈다.
  6. 문구(걸린 지시 8절 적용): 주사위 위 "실물 주사위의 면을 고르세요." 안내 문장을 지운다(더블·감옥 안내는 할 일을 바꾸는 상태라 남긴다). 찬스·사회사업기금 카드 목록에서 이동 카드 아래 "카드의 칸으로 이동"을 지운다 - 제목이 이미 "…로 이동"이다. 부제가 없는 카드도 목록의 줄 높이는 다른 카드와 같게 둔다(걸린 지시 8절 3항).

  8. 위 2~5는 측정 도구로 매번 잰다(0.22.5). 사람 눈 확인 전에 도구가 통과해야 한다.

0.21. 보드 위 결과 · 부지와 독점 안내 · 안쪽 말 (2026-11-16)

  1. 승리·공동 승리는 마지막 보드를 유지한 채 그 위 팝업으로 표시한다. 아이패드 가로에서는 보드 중앙에 놓고, 결과 중 봇·시계·이동·칸 강조 애니메이션은 멈춘다. 새 판 준비, 시간제 결산 수정은 기존 동작을 유지한다. 저장된 결과를 다시 열어도 동일하다. 결과는 이 두 행동으로 닫고 배경 보드를 조작하지 않는다.

  1. 새 파일 bot.js(MC_BOT): 화면과 무관한 판단 함수만 둔다. decide(board, p, ctx)는 다음 행동 하나를 돌려준다 - jailCard · jailPay · roll · buy · decline · auctionHuman · pay · fixRent · ack · draw · card · utilityRoll · mortgage · release · build · sell · sellAll · offer · humanFunds · bankrupt · next · wait(offer는 거래 제안, sellAll은 한 채 팔기가 막힐 때 그 색 건물 모두 팔기, humanFunds는 카드 지시로 사람이 낼 돈이 모자랄 때 그 사람의 돈 마련 창 열기). 색 맞추기 제안과 돈 마련 거래 요청은 차례당 한 번씩 따로 센다. ctx는 차례 수 · 최근 제안 기록 · 이번 차례 거래 요청 여부 · 경매 상대가 봇인지. 실제 판 변경은 기존 board.js 기록 함수만 쓴다(새 규칙 계산 없음). auction(board, index, auto)는 0.19.3 2항의 낙찰자 · 금액(또는 유찰), accept(board, offer, p)는 0.19.3 6항 판단, shuffle(ids, random)와 drawCard(decks, deck, held, random)는 카드 더미를 다룬다. 무작위는 인자로 받아 시험에서 고정한다.
  2. 판 저장 항목 추가(세션 s): auto:[false,false], speed:1|2|4|8, decks:{chest:{order,next},chance:{order,next}}, botMemo(최근 제안). 없는 옛 판은 읽을 때 기본값으로 채운다. 감옥 탈출 카드를 가진 동안 그 카드는 다시 섞을 때 빼고, 쓰면 더미 맨 아래로 돌아간다(남은 더미에 없을 때만 덧붙인다). 한 차례 걸음 상한(data.js maxStepsPerTurn)을 넘으면 판을 일시정지하고 걸음 수를 비운다.
  3. app.js 돌리개: 화면을 그릴 때마다 조건(진행 화면 · 현재 차례가 오토 · 판이 돌고 있음 · 창 · 메뉴 닫힘 · 이동 연출 끝 · 끌기 아님)을 보고, 맞으면 기본 900ms ÷ 배속 뒤 decide 한 걸음을 기존 run()으로 실행한다. 조건이 깨지면 예약을 지운다. 이동 연출 간격도 배속으로 나눈다. 한 걸음마다 되돌리기 기록이 남는다.
  4. 사람에게 온 거래 요청은 기존 대화상자에 거래 내용(주는 것 · 받는 것)과 수락 · 거절 두 단추만 띄운다.

0.8. 여러 채 건설 (2026-11-09)

진행 화면에 집 짓기 버튼을 두고 보유 도시와 권리증에서도 같은 색 건설 계획으로 진입한다. 같은 색의 도시별 현재 건물과 건설 후 목표를 한 화면에 표시하고, 각 도시의 추가/빼기 버튼 및 모든 도시 주택1~4채/호텔 목표 버튼으로 수량을 정한다. 빼기는 아직 짓지 않은 계획만 취소하며 기존 건물을 팔지 않는다. 확정 전 총 건축비·남을 현금·도시별 임대료를 표시한다. 선택은 저장하지 않고 확정할 때만 실제 건설한다.

도시별 목표는 현재 이상, 호텔 포함5단계 이하이며 색 안의 최대/최소 차이는1 이하이어야 한다. 가장 적은 도시부터 한 채씩 기존 건설 함수로 검증한다. 독점·저당·현금·은행 주택32/호텔12 조건을 지킨다. 어느 단계라도 불가하면 전체 계획을 적용하지 않으며 이유를 표시한다. 한 번 되돌리기로 전체 건설을 복원한다. 작업 순서: 문서 → 순수 일괄 건설/시험 → 계획 UI → 실제 브라우저 확인.

0.5. 통합 방식·플레이어 색 확정

아빠·서우 카드에서 고르는 색은 시작 부지가 아니라 말·소유 배경·차례 아바타·현재 위치 강조의 플레이어 색이다. 파랑/분홍/초록/주황/보라/회색의 여섯 가지를 색 이름과 함께 선택한다. 상대 색을 선택하면 두 색을 교환해 구분을 유지한다. 새 판에 선택한 색을 저장하고 새로고침·이어하기·되돌리기에도 보존한다. 기존 판의 색 정보가 없으면 기존 파랑/분홍을 사용한다. 준비의 색 변경은 진행 중인 판을 바꾸지 않고 새 판 시작 시 적용한다.
