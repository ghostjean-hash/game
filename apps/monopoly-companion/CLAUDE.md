# 모노폴리 클래식 동행

## 1. 목적
실물 클래식 보드를 사용하는 부모와 초등학생 2인용 진행 도우미. 게임 복제나 디지털 은행이 아니다.

## 2. 기준
기획·규칙·작업 계획은 `docs/planning.html`이 원본이다. 수정 순서는 문서 → 코드 → 검증.
공식 기본 규칙과 제안한 우리 집 규칙을 명확히 구분한다. 판별 도시명·금액은 실물 카드 우선.

## 3. 구현
빌드·외부 패키지 없이 HTML/CSS/일반 JS. index.html 직접 열기와 정적 서버 모두 지원한다. 홈 화면 추가 설정은 app.webmanifest(가로 · standalone).
data.js는 한국판 40칸/지폐/아빠·서우 기본 이름, core.js는 시간·차례·결산, board.js는 말·현금·권리증·건물·저당의 순수 기록 함수, manager.js는 간단 규칙, app.js는 한 화면 준비·보드 진행·저장을 담당한다.
실물 주사위 두 면을 각각 1~6의 점 모양 버튼에서 선택한다. 웹 굴림 버튼은 넣지 않는다. 예외: 오토 봇 차례만 웹 무작위 주사위와 섞은 카드 더미를 쓴다(bot.js, planning.html 0.19, 수치는 data.js bot). 사용자 추가 사진의 도시 권리증 22장과 카드 28장(사회사업기금13/찬스15)을 data.js에 등록했다. 일반 임대료·독점·건축비는 자동 계산하며 카드 제목을 고르면 지시를 처리한다. 카드 종류·제목·금액을 함께 표시하고 직접 입력 진입은 제공하지 않는다. 기존 판은 hydrate로 수치를 보완하되 현금·소유·건물·차례를 보존한다. 원본 사진 전체·사람·배경은 공개하지 않는다. 사용자 요청으로 추출한 특수 칸 그림만 assets/board에 둔다.
아이패드 가로형에서 오른쪽 칸 맨 위는 시계와 메뉴(확대·일시정지·마무리·기록 맞추기·되돌리기·규칙·준비), 그 아래 차례·위치·잔액과 현재 처리, 맨 아래 관리 아이콘 넷이다. 보드와 오른쪽 칸은 가용 폭·높이 안에서 위아래를 맞추고, 오른쪽 칸은 492:992 비율로 함께 줄인다(planning.html 0.20, 종전 0.15 정정). 준비는 Safari 도구 막대로 높이가 줄어도 아이패드 가로 한 화면에 맞춘다. 오토는 실제 행동만 한 번 예약하며 준비·사람 차례·일시정지·창·메뉴·숨김 상태에서는 반복 확인하지 않는다. 보드는 확대(1~3배)·드래그되고 확대 중 현재 말 칸을 따라간다(planning.html 0.12.2). 도시 기본 색 띠 대신 안쪽에 구획선·빈 칸 배경 없는 내부 세 자리로 주택 한 채씩 놓고 네 번째는 첫 칸 둘째 줄, 호텔은 두 칸으로 그린다. 소유자는 부지 전체 배경과 이름으로 통일하고 독점을 표시한다. 특수 칸 그림 크기는 소유 여부와 무관하다. 화폐 M은 가는 세리프 기호로 숫자와 구분한다.
한 판은 한 기기의 로컬 저장만 사용한다. 다른 게임·공용 코드·클라우드 설정은 변경하지 않는다.
준비는 스탠다드/공식 단축 30분/공식 단축 60분 하나로 선택한다(planning.html 0.9). 스탠다드는 mode:'standard', minutes:null, 부지 없이 M1500, 경과 시간 표시이며 자동 종료하지 않는다. 공식 단축은 mode:'short', 보드 rule:'short'로 1951 단축 게임 원문을 따른다 - 권리증 2장씩 무작위 지급·인쇄 가격 지불, 주택 3채에서 호텔(4채 단계 없음, 호텔은 균등 판정 네 번째 단계), 호텔 판매는 절반 환급 후 3채, 결산 호텔은 주택 4채 값, 시간제 결산(준비·결산 10분 예약). 비공식 빠른 시작(주황·빨강 세트 지급)은 새 판 선택에서 뺐고, mode 없는 기존 빠른 시작·45분·기본 판은 저장된 규칙 그대로 이어간다. playerColors는 두 팔레트 ID를 저장하며 색이 없는 기존 판은 파랑/분홍이다. 상대 색을 고르면 교환한다. 말·소유 배경·차례·현재 위치 글로우에 같은 색을 쓴다. UI 아이콘과 M 중간 두 줄은 SVG로 그린다. 사용자 답변과 최신 구현 이력은 NEXT-SESSION.md/PROGRESS.md를 참조한다.

결과는 마지막 보드 위 팝업이며 새 판 준비·결산 수정으로 닫는다. 말은 보드 중앙 빈 공간 가장자리에서 해당 부지를 향하는 플레이어 색·이름 표식이다. 같은 칸의 두 말은 안쪽으로 간격을 두고 이동·확대 추적과 함께 움직인다. 부지 창은 소유·가격·임대료·독점 묶음·건설비를 구분한다. 도시 외 역4곳·공공 기관2곳도 독점 표시하며 메뉴→규칙→독점에서 효과를 볼 수 있다. 계산·표시 원본은 board.js holdingInfo/deedInfo 및 data.js, 기준 planning.html 0.21이다.

## 4. 확인
`node --test apps/monopoly-companion/tests/*.test.mjs`.
브라우저에서 준비 → 진행 → 규칙 → 결산, 새로고침 복원과 좁은 화면을 확인한다.
화면 규칙(planning.html 0.22.2: 기준 아이패드 프로 12.9 가로 1366×950·1366×1024, 팝업 화면 안·X만으로 닫기 금지·48px 단추)은 개발 서버(`node scripts/dev-server.mjs 8010`)를 켠 뒤 `node apps/monopoly-companion/tests/screen-audit.mjs audit <결과폴더>`로 33장면을 재서 문제 0이어야 한다. 스타일 구조만 바꿀 때는 `styles` 방식으로 전후 적용 스타일 지문을 떠서 같음을 본다. 새 스타일은 style.css 끝 "0.22 화면 규칙" 구간의 정의값(--touch 등)을 쓴다.

돈 마련·부지 관리 창은 현재 현금/부족액, 행동별 받을·낼 돈과 임대료 변화, 실행 불가 이유를 보여준다. board.js의 assetOptions가 실제 기록 함수로 미리 계산한다. 경매와 거래는 hidden 금액 필드와 화면 숫자패드만 사용한다. 집 건설·판매·저당은 차례와 무관하지만 독점·균등·건물 정리·저당·현금·은행 재고 조건을 지킨다. 상세 기준은 docs/planning.html 0.6이다.

여러 채 건설은 진행의 집 짓기·부지 관리·권리증에서 색 세트별 도시 목표를 선택한다. board.js buildPlan은 기존 build를 적은 도시부터 적용해 원본을 보존하고 전체 실패 시 미반영한다. planning.html 0.8 참조.
