# 러시아워 보드 안쪽 개편 (설계)

작성: 2026-09-06 / 대상 일감: T-116 후속(B) / 기준 문서: `games/rushhour/docs/01_spec.md` 0장·8.2 · `docs/02_data.md` 2장 · 기획서 Ⅲ권 3.1

## 1. 이 설계가 하는 것과 안 하는 것

1.1. 앞 판(A, `bc0ca32`)은 **바깥틀**이었다 - 무엇이 어디에 얼마만 하게 놓이는가. 이 판(B)은 **보드 한 칸 안에서 벌어지는 일**이다. 사용자가 "본질은 B"라고 지목한 자리고, 범위도 사용자가 정해 뒀다 - **블록 경계 · 캐릭터 크기 · 출구 표현** 셋.

1.2. 경계선 확인. 기획서 Ⅲ권 3.1이 "플레이가 벌어지는 네모 **안쪽은 게임이 전부 갖는다**"라고 정했다. 그래서 이 판은 **러시아워 폴더 안에서 끝난다.** 공용 부품(`shared/frame/`)을 새로 만들거나 고치지 않는다.

1.3. 위험 등급은 낮다. 영속 데이터·공용 인터페이스·재화 어느 것도 안 걸린다. 다만 **틀려도 기계 검사에 안 잡히고 화면으로만 드러나는 변경**이라(A판과 같다), 실측과 눈 확인을 구현과 같은 판에서 돌린다.

1.4. 자산(그림 파일)은 늘리지 않는다. 지금 있는 것은 통 블록 넷(`a_h2`·`a_h3`·`a_v2`·`a_v3`) · 표정 시트 하나(`c_cell_16_a`) · 주인공 하나(`target.png`)뿐이고, 새 캐릭터를 그리는 것은 이 판의 범위 밖이다. **그림을 늘리지 않고 배치·크기·색·테두리만으로 푼다.**

## 2. 지금 무엇이 잘못돼 있나 (실측 2026-09-06)

네 크기에서 스테이지 40(블록 여섯)을 띄워 재고 눈으로 봤다.

| 화면 | 보드 폭 | 한 칸 | 고정 테두리 3px이 칸에서 차지하는 비율 |
|---|---|---|---|
| 작은 폰 375×667 | 296 | 49.4 | 6.1% |
| 폰 430×932 | 344 | 57.3 | 5.2% |
| 태블릿 820×1180 | 680 | 113.4 | **2.6%** |
| 폰 가로 932×430 | 282 | 47.0 | **6.4%** |

2.1. **경계 두께가 화면 크기를 안 따라간다.** 블록 안쪽 테두리가 `3px`(주인공 `4.5px`) 고정이라, 칸 대비 두께가 폰 가로 6.4%에서 태블릿 2.6%로 **2.5배 벌어진다.** 화면이 커질수록 블록 경계가 가늘어져 덩어리가 흐려진다. 러시아워 `CLAUDE.md` §6이 "셀 크기는 `--cell` 한 곳에서 파생. px 하드코딩 금지"라고 못박은 자리를 그대로 어기고 있다. 같은 종류가 더 있다 - 블록 그림자 `0 1px 3px`, 힌트 강조테 `4px`·번짐 `14px 4px`, 눈물 `3vmin`, 장식 크기 `2.4vmin`과 앵커 `calc(8% - 10px)`. **vmin·px는 화면 기준이라 보드 크기와 무관하게 논다.**

2.2. **주인공이 판에서 가장 안 보인다.** 여섯 블록 중 주인공만 배경이 투명이고(`rgba(0,0,0,0)`, 꾸미기 기본값 `target:{bg:false}`) 나머지 다섯은 파스텔로 채워져 있다. 크림 바닥이 그대로 비쳐서, **화면에서 제일 중요한 조각이 배경과 가장 가깝다.** 붉은 테두리 하나가 그걸 혼자 떠받치고 있다.

2.3. **블록이 "한 덩어리"로 안 읽힌다.** 기본 스타일 밥풀이(`tiled:true`)는 1칸 캐릭터를 블록 길이만큼 반복한다 - 가로3 블록은 같은 얼굴 셋이 빈틈없이 나란하다. 묶어 주는 것이 배경색 하나뿐이라 "한 조각"이 아니라 "세 마리가 붙어 서 있다"로 읽힌다. **슬라이딩 블록 퍼즐에서 조각 단위 인지는 규칙 그 자체다** - 이게 흐리면 무엇을 잡아야 몇 칸이 움직이는지가 매번 헷갈린다.

2.4. **캐릭터 기준 크기가 둘이다.** 밥풀이는 정사각 한 칸을 꽉 채우는 얼굴이고, 주인공 포니는 `320×160`(2:1) 전신이라 몸통 높이가 칸의 4분의 3쯤이다. 한 판에 스케일 두 개가 섞여 있어 주인공이 작아 보인다.

2.5. **출구가 보드 밖에 떠 있고, 무엇인지도 어긋나 있다.**

- 출구 표시(`.exit`)가 보드 오른쪽 **바깥** 0.95칸에 있다(폰 47px ~ 태블릿 108px). 크림 보드가 끝난 어두운 플럼 배경 위에 화살표만 뜬다.
- 보드 안 출구 길(`.exit-lane`)은 오른쪽 1.6칸뿐이라, 그 위에 블록이 올라오면 절반이 덮여 **출구 행이 어느 줄인지 한눈에 안 들어온다.**
- **문서와 코드가 어긋나 있다.** 사양 0.4·0.5는 "출구 밖으로 이어지는 출구 길과 게이트", "주인공을 **집**까지 데려다준다"이고 `render.js` 주석도 "보드 밖 집(🏠)"이라 적어 놨는데, 실제로 그리는 것은 **화살표 SVG**다. 집은 어디에도 없다. 어디로 왜 나가는지가 그림으로 서 있지 않다.

2.6. **색을 크림 하나에서만 골랐다.** 상점 보드 테마가 다섯인데(`cream`·`sky`·`mint`·`lavender`·`peach`) 바닥·격자선·출구 색을 통째로 갈아 끼운다. 반면 주인공 테두리 `TARGET_BORDER`(`#e0555f`)와 블록 색조 `BLOCK_TINTS` 여섯은 고정이다. **크림에서 고른 값이 라벤더·복숭아에서 성립하는지 아무도 안 봤다.**

2.7. **표정이 이야기와 어긋난다.** 표정 컷 16개를 위치 해시로 무작위 배정해서, 스테이지 40에서는 세로3 블록 셋이 **화난 얼굴**로 나온다. 사양 0.5는 "친구들이 길을 막고 있다 → 살살 비켜 준다"인데, 화난 얼굴은 "비켜 주기 싫다"로 읽혀 톤이 반대다.

2.8. **문서-코드 어긋남 하나 더 (사양 0.3).** 사양은 "가로2=고양이, 가로3=강아지, 세로2=병아리, 세로3=펭귄, 주인공=토끼"인데 실제는 스타일 둘(포니 `a` / 밥풀이 `c`)에 주인공은 포니 하나다. 종류별 동물은 캐릭터를 SVG로 그리던 시절의 사양이고, 2026-07-02에 그림 시트 방식으로 갈아엎으며 코드에서 사라졌는데 **사양만 남았다**(같은 정리를 `colors.js`에서는 2026-09-06에 이미 했다 - 02_data 2.1 각주).

## 3. 무엇을 바꾸나

### 3.1. 수치를 칸에서 파생시킨다 (2.1)

보드 안쪽 수치를 `--cell` 기준 한 곳으로 모은다. `.board` 스코프에 굵기 변수를 두고 나머지가 거기서 파생한다.

| 지금 | 바꾼 뒤 | 폰 가로(칸 47) | 태블릿(칸 113) |
|---|---|---|---|
| 블록 테두리 `3px` | 칸의 5% | 2.4px | 5.7px |
| 주인공 테두리 `4.5px` | 그 1.5배 | 3.5px | 8.5px |
| 블록 그림자 `0 1px 3px` | 칸 파생 | 얇게 | 두껍게 |
| 힌트 강조 `4px` / 번짐 `14px 4px` | 칸 파생 | | |
| 장식 크기 `2.4vmin` · 앵커 `calc(8% - 10px)` | 칸 파생(%만) | | |
| 눈물 `3vmin` | 칸 파생 | | |

- **파티클(`.confetti` `6vmin`)은 그대로 둔다.** 그건 보드 조각이 아니라 화면 축하 연출이라 화면 기준이 맞다.
- 값은 CSS 변수 한 곳(`.board` 스코프)에 두고 파생한다. 04_conventions 3.2가 정한 `--rh-*` 토큰 자리와 같은 층이다.

### 3.2. 블록을 "잡을 수 있는 카드 한 장"으로 (2.3 · 2.4)

캐릭터를 늘리지 않고 **블록이라는 그릇**을 세운다.

```
지금                              바꾼 뒤
┌───┬───┬───┐                    ╭─────────────╮
│(얼)(얼)(얼)│  얼굴 셋이         │ (얼) (얼) (얼) │  카드 한 장 위에
└───┴───┴───┘  빈틈없이 나란      ╰─────────────╯  얼굴 셋이 얹힘
```

- **카드 안쪽에 여백을 준다.** 캐릭터를 칸 가득에서 살짝 줄여, 블록 바깥선과 캐릭터 사이에 테두리 두께만큼 숨을 둔다. 여백이 생기는 순간 얼굴 셋이 "붙어 선 셋"이 아니라 "카드 하나 위의 셋"으로 읽힌다.
- **바깥선과 그림자를 칸에서 파생시켜 굵힌다**(3.1). 조각의 윤곽이 화면 크기와 무관하게 같은 굵기로 보인다.
- **캐릭터 기준 크기를 카드 여백으로 통일한다.** 밥풀이(정사각 꽉 참)와 주인공 포니(2:1 전신)의 스케일이 다른 것은 자산 문제라 못 없애지만, 둘 다 같은 여백의 카드 위에 놓이면 **기준선이 하나가 된다.**
- 모서리 둥글기도 칸에서 파생시킨다 - 지금은 `--r-2` 고정이라 태블릿에서 상대적으로 각져 보인다.

### 3.3. 출구를 "집으로 가는 길"로 (2.5)

문서가 이미 집이라고 정해 뒀고 코드 주석도 그렇게 적었다. **docs가 진실이다**(루트 CLAUDE.md 6.1) - 코드를 문서에 맞춘다.

```
지금                                    바꾼 뒤
┌──────────────┐                       ┌──────────────┐
│              │                       │              │
│         ▓▓▓▓ │  ➡   화살표가 보드     │░░░░░░░░░░▓▓▓▓│ 🏠  출구 행 전체가
│              │      밖 어두운 배경    │              │     옅은 길, 끝이 짙고
│              │      위에 떠 있음      │              │     보드 밖은 집
└──────────────┘                       └──────────────┘
```

- **출구 행을 왼쪽 끝까지 옅은 길로 깐다.** 지금은 오른쪽 1.6칸만이라 블록이 덮으면 사라진다. 행 전체가 아주 옅게 깔려 있으면 **블록이 올라와도 어느 줄로 나가는지가 남는다.** 오른쪽 끝으로 갈수록 짙어져 방향이 보인다.
- **보드 밖 표시를 집으로 바꾼다.** 화살표 SVG를 집 모양으로 다시 그린다(자산 추가 없이 인라인 SVG). 방향은 길의 농도 변화와 출구 행 위치가 이미 말해 주므로, 집이 화살표를 대신한다.
- **집을 보드 테두리에 붙인다.** 지금은 보드 밖에 떠서 어두운 배경 위에 홀로 있다 - 길이 보드 가장자리를 넘어 집까지 이어지게 해서 "안에서 밖으로 나간다"를 한 줄로 만든다.
- 클리어 퇴장 애니(`translateX(175%)`)의 도착점을 집 자리에 맞춘다. 지금 값은 화살표 자리 기준이라 집으로 바꾸면 어긋난다.

### 3.4. 주인공을 가장 눈에 띄게 (2.2)

- **투명 배경은 유지한다.** 무지개 갈기 포니에 파스텔 바탕을 깔면 색이 싸운다(색 스킨을 2026-07-02에 없앤 것과 같은 이유고, 꾸미기 기본값 `target:{bg:false}`도 그 결론이다). 기본값을 뒤집지 않는다.
- 대신 **바닥에서 떠 있게** 만든다 - 주인공 블록에만 바깥 그림자와 옅은 후광(출구색 계열)을 준다. 채우지 않고도 판에서 하나만 다르게 보인다.
- 테두리는 3.1대로 일반의 1.5배를 유지하되 칸에서 파생시킨다.
- 꾸미기에서 배경을 켠 사용자에게도 깨지지 않아야 한다 - **`bg` on/off 두 경우를 다 본다.**

### 3.5. 표정을 이야기에 맞춘다 (2.7)

- 평상 배정 풀에서 **화난 컷을 뺀다.** 시트 16컷 중 화난 컷은 `sadFaces`·상황 연출용으로만 남긴다.
- 이건 자산 변경이 아니라 **어느 컷을 언제 쓰느냐**의 데이터 변경이라 `styles.js`에서 끝난다.
- 손대는 김에 표정을 정보로 쓰고 싶은 유혹이 있지만(막혔을 때 곤란한 얼굴 등) **이 판에서는 안 한다** - 기능 추가고, 3.2가 만든 조각 인지를 먼저 확인해야 한다.

### 3.6. 테마 다섯 전부에서 고른다 (2.6)

- 3.2·3.3·3.4가 정하는 색을 **크림 하나가 아니라 다섯 테마 전부에서** 본다.
- 주인공 테두리 `#e0555f`가 라벤더·복숭아에서 성립하는지 확인하고, 안 되면 테마별 값을 준다(그 경우 `BOARD_THEMES` 항목에 칸이 하나 는다).
- 출구 길 색은 이미 테마가 준다(`exit`). 3.3이 길을 넓히면 그 색이 차지하는 면적이 커지므로 **다섯 테마 전부에서 블록 색조 여섯과 부딪히지 않는지** 본다.

### 3.7. 문서를 코드에 맞춘다 (2.5 · 2.8)

- **사양 0.3** - 종류별 동물(고양이/강아지/병아리/펭귄)과 "주인공=토끼"를 실제(스타일 둘, 주인공 포니)로 정정한다. 코드가 사용자 결정(2026-07-02)을 반영한 쪽이고 사양만 안 따라왔다.
- **사양 0.5** - "토끼"를 주인공으로 고친다. 6.1·6.6도 같은 말이 남아 있다.
- **사양 8.2** - 보드 안쪽 규격 절을 새로 쓴다(블록 카드·경계 굵기 파생·출구 길과 집). 지금 8.2는 보드 위 카드까지만 적혀 있고 보드 안쪽은 백지다.
- **02_data 1장** - 칸 파생 수치가 CSS 변수로 가면 그 자리를 적는다.

## 4. 무엇으로 확인하는가

4.1. **기계 검사** - 이 판도 자리와 색이라 순수 로직 시험으로 안 잡힌다. 러시아워 자체 시험과 루트 검사가 그대로 통과하는 것만 본다(회귀 없음). **이 층이 화면을 못 본다는 사실을 결과에 적는다** - 걸음 B에서 기계 검사 225건이 전부 통과하는데 버튼이 죽어 있던 적이 있다.

4.2. **실측** - 2장의 표를 같은 방식으로 다시 재고 아래를 확인한다.

- 네 크기 전부에서 **블록 테두리가 칸 대비 같은 비율**인가(지금 2.6%~6.4%가 한 값으로 모이는가)
- 네 크기 전부에서 겹침 0 · 페이지 세로 스크롤 0 · 잘려 나간 요소 0(A판이 세운 조건 유지)
- 출구 집이 보드 오른쪽 바깥에서 **잘리지 않는가** - 3.3이 집을 보드에 붙이면 오른쪽 여백 계산(`--exit-ratio` 0.1583)이 함께 움직인다. **이 값은 A판이 보드 크기 계산에 쓰고 있어서, 건드리면 보드 폭이 바뀐다**(A판의 회귀 자리다)
- 주인공 블록이 `bg` on / off 두 경우 다 판에서 가장 눈에 띄는가

4.3. **눈으로** - 네 크기 × 테마 다섯을 지금 것과 나란히 놓고 본다. **크기마다 다 본다** - 세로만 보고 넘어가 가로에서 깨진 것을 뒤늦게 잡은 적이 있다(걸음 B).

4.4. **밟는 경로** - 판 고르기 → 플레이 → 블록 드래그(가로·세로·막힘) → 되돌리기 → 힌트 → 리셋 → 클리어 퇴장 → 결과 카드. 특히 **클리어 퇴장이 집까지 정확히 가는가**(3.3에서 도착점을 옮긴다), **힌트 강조가 새 테두리 굵기와 안 부딪히는가**(둘 다 블록 바깥선이다).

4.5. **꾸미기 조합** - 스타일 둘(포니 / 밥풀이) × 배경 on/off × 테두리 on/off. 3.2가 여백을 도입하므로 **테두리를 끈 경우에 여백만 남아 붕 뜨지 않는지** 본다.

## 5. 하지 말 것

5.1. 그림 자산을 새로 그리거나 늘리지 않는다(1.4). 캐릭터 종류를 늘리는 것은 별도 판이다.

5.2. 공용 부품(`shared/frame/`)을 고치지 않는다. 이 판은 러시아워 폴더 안에서 끝난다.

5.3. 게임 규칙·기능을 더하거나 빼지 않는다 - 이동·수 세기·별·골드·힌트·콤보 전부 그대로다. 표정도 **어느 컷을 언제 쓰느냐**만 바꾸고 새 연출을 만들지 않는다(3.5).

5.4. 저장·진행·지갑·상점을 건드리지 않는다. 3.6이 `BOARD_THEMES`에 칸을 더할 수는 있지만 저장 형식은 그대로다(테마 id만 저장한다).

5.5. 바깥틀(A판이 정한 자리·크기·색 계통)을 다시 열지 않는다. 대기 중인 사용자 결정 둘(가로 정중앙 43px, 폰 세로 위 여백 222px) 중 **위 여백은 이 판에서 출구 표현이 바뀌면 다시 재 본다** - 3.3이 보드 오른쪽 여백을 건드리기 때문이다. 가로 정중앙은 이 판과 무관하니 그대로 대기.

5.6. 배경(보드 밖 플럼)에 무늬·그림을 넣지 않는다. A판에서 이미 범위 밖으로 정했다.

5.7. 다른 게임 여섯에 손대지 않는다(사용자 결정 - 러시아워를 기준 게임으로 완전히 올리기 전에는).

## 6. 남은 결정과 가정

6.1. **가정 - 사양 0.3의 동물 종류는 되살리지 않는다.** 되살리려면 캐릭터 넷을 새로 그려야 하고 그건 자산 판이다(5.1). 코드가 사용자 결정(2026-07-02 그림 시트 전환)을 반영한 쪽이므로 **문서를 코드에 맞춰 정정한다**(3.7). 사용자가 종류별 동물을 되살리길 원하면 이 가정을 뒤집고 별도 판으로 세운다.

6.2. **가정 - 출구는 집이다.** 사양 0.4·0.5와 코드 주석이 이미 집이라 말하고, 화살표만 어긋나 있었다. 문서가 진실이라는 규칙(6.1)대로 코드를 문서에 맞춘다.

6.3. **위험 - `--exit-ratio`는 A판의 보드 크기 계산에 걸려 있다.** 3.3이 집 자리를 바꾸면 이 값이 함께 움직이고, 그러면 **네 크기 전부에서 보드 폭이 바뀐다.** 앞 판이 어렵게 세운 값이라 여기서 깨면 A판이 통째로 흔들린다. 4.2가 이걸 확인 조건으로 못박는다.

## 7. 모델 배정

영속 데이터·공용 인터페이스·재화 어느 것도 안 걸린다. 다만 A판과 마찬가지로 **기계 검사에 안 잡히고 화면으로만 드러나는 변경**이고, 6.3의 회귀 위험이 앞 판 결과물을 건드린다. 구현·실측·눈 확인을 같은 판에서 돌리고, 독립 검사를 커밋 전에 최소 한 번 넣는다.
