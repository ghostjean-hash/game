# 러시아워 플레이 화면 바깥틀 정리 (설계)

작성: 2026-09-06 / 대상 일감: T-116 / 기준 문서: `games/rushhour/docs/01_spec.md` 8장 · 기획서 Ⅲ권 2.1 · 3.1

## 1. 이 설계가 하는 것과 안 하는 것

1.1. 사용자 지시는 **"게임 안 UI/UX가 개판"**이고, 범위는 **A(플레이 화면 바깥틀)**로 확정됐다. 보드 안쪽(블록 경계·캐릭터 크기·출구 표현)은 본질적으로 고쳐야 하지만 **다음 판으로 미룬다**(사용자 결정 2026-09-06).

1.2. 그래서 이 판이 손대는 것은 **자리와 크기와 색**이다 - 무엇이 어디에 얼마만 하게 놓이는가. 보드 한 칸 안에서 벌어지는 일은 하나도 건드리지 않는다.

1.3. 경계선 확인. 기획서 Ⅲ권 3.1이 "플레이 화면 - 플랫폼 몫은 화면 바깥 테두리와 버튼 **부품**, 게임 몫은 그 버튼들을 **어디에 놓을지와 안쪽 전부**"라고 정했다. 그래서 **이 판은 러시아워 폴더 안에서 끝난다.** 공용 부품을 새로 만들거나 고치지 않는다. 여기서 나온 결론이 둘째 게임에서 또 필요해지면 그때 규격으로 올린다(기획서 7.3).

1.4. 위험 등급은 낮다. 영속 데이터를 만지지 않고 공용 인터페이스도 안 건드린다. 다만 **바로 앞 걸음이 같은 파일을 고쳤으므로**(걸음 C, `f1d1055`) 그 커밋 위에서 시작한다.

## 2. 지금 무엇이 잘못돼 있나 (실측 2026-09-06)

네 크기에서 실제로 재고, 화면으로 눈으로 봤다.

| 화면 | 보드 크기 | 보드가 쓰는 폭 | 상단→정보 빈칸 | 보드→조작 빈칸 |
|---|---|---|---|---|
| 작은 폰 375×667 | 296 | 79% | 58px | 68px |
| 폰 430×932 | 344 | 80% | **165px** | **174px** |
| 폰 가로 932×430 | 258 | **28%** | 6px | **-208px (겹침)** |
| 태블릿 820×1180 | 480 | 59% | **257px** | **267px** |

2.1. **가로 화면은 배치 규칙이 통째로 안 먹는다 (회귀 · 가장 큼).** 가로 격자를 `.rushhour.page[data-screen="play"]`에 걸어 뒀는데, 공용 프레임이 들어오며 그 안에 화면 래퍼(`#screen-play`)가 하나 생겼다. 상단 줄·보드·조작은 전부 그 래퍼 **안**에 있어서 격자 칸에 들어가지 못한다. 결과가 셋이다 - 보드가 조작 줄을 **50px 파고들어 겹치고**, 화면이 왼쪽 365px에 몰려 **오른쪽 567px이 통째로 비고**, 보드가 폭의 28%만 쓴다. 인계문에 "목표 밖 발견"으로 적혀 있던 것이 이것이다.

2.2. **화면이 커져도 보드가 안 커진다.** 보드 폭 상한이 480px로 박혀 있어 태블릿에서 남는 200px을 못 쓴다. 화면이 커질수록 **여백만 커진다.**

2.3. **같이 봐야 할 값이 화면 양 끝으로 갈렸다.** 이동 수는 맨 위 줄에, 남은 시간은 보드 바로 위에 있다. 세로로 300px 떨어져 있고, 그 사이에 아무것도 없다. 게다가 "골드·이동" / "모드·스테이지·난이도" / "남은 시간"이 서로 다른 모양의 덩어리 셋이라 한 화면에 알약 모양이 세 종류다.

2.4. **눈에 띄는 순서가 실제 중요도와 반대다.** 가장 밝은 흰색이 이전·다음·리셋이고 노란색이 힌트인데, 놀이 중 제일 자주 누르는 되돌리기는 회색으로 죽어 있다. 다섯 개가 2줄(2개)·3줄(3개)로 갈렸고 폭 규칙도 없다.

2.5. **색 계통이 넷이다.** 어두운 자주 배경 · 크림 보드 · 흰 버튼 · 노란 힌트 · 초록 타이머 막대가 서로 관계가 없다. 그리고 배경이 아무것도 없는 단색이라 2.2의 빈 공간이 더 도드라진다.

## 3. 무엇을 바꾸나

### 3.1. 세로 배치 - 한 덩어리로 모으고 조작을 엄지 쪽에 붙인다

```
지금                                바꾼 뒤
┌───────────────────────┐          ┌───────────────────────┐
│ ← [🪙0][이동0] 🔊 ⚙   │          │ ←              🔊 ⚙   │  조작 아이콘만
│                       │          │                       │
│        (빈 곳)         │          │        (빈 곳)         │
│                       │          │ ┌───────────────────┐ │
│   [오리지널 7 입문]     │          │ │오리지널·7·입문     │ │  판 이름
│      [ 1:40 ]         │          │ │🪙 0  이동 0  1:40 │ │  놀이 값 셋
│   ┌─────────────┐     │          │ ├───────────────────┤ │
│   │    보드      │     │          │ │                   │ │
│   └─────────────┘     │          │ │       보드         │ │  더 크게
│                       │          │ │                   │ │
│        (빈 곳)         │          │ └───────────────────┘ │
│                       │          │                       │
│ [‹이전]    [다음›]     │          │ [되돌리기][힌트][리셋] │  주 조작
│ [되돌리기][힌트][리셋] │          │  ‹ 이전        다음 ›  │  판 이동
└───────────────────────┘          └───────────────────────┘
```

- **골드·이동·시간을 한 줄로 모아 보드 바로 위에 붙인다.** 셋 다 놀면서 번갈아 보는 값이다. 상단 줄에는 되돌아가기·소리·환경설정 셋만 남는다 - 그 줄은 조작만 있는 줄이 된다.
- 판 이름(모드·스테이지 번호·난이도)은 그 위에 작게 한 줄. 놀이 중에 계속 볼 값이 아니라 "지금 어디" 표시다.
- **정보 줄과 보드를 한 카드로 붙인다.** 지금은 카드 셋이 따로 떠 있어 덩어리가 안 만들어진다.
- 남는 세로는 **위쪽으로 몬다.** 조작은 엄지가 닿는 아래에 붙어 있어야 하고, 보드는 눈높이보다 조금 위가 편하다. 지금처럼 위아래를 똑같이 나누면 덩어리가 화면 한가운데 붕 뜬다.

### 3.2. 보드 크기 - 화면이 주는 만큼 쓴다

- 폭 상한 `480px`을 **`720px`로 올린다.** 태블릿에서 보드가 480 → 680이 된다(폭 계산이 먼저 걸린다).
- 세로 기준 `60vh`는 **정보 줄과 조작 줄이 실제로 먹는 높이를 뺀 값**으로 바꾼다. 지금은 어림값이라 세로가 남아도 못 쓴다.
- 폰 세로(430)에서는 **폭이 병목이라 보드가 더 안 커진다.** 이건 물리적 한계라 여백이 남는 것 자체는 못 없앤다 - 3.1의 "덩어리로 모으기"가 그 여백을 의미 있게 만드는 처방이다.

### 3.3. 가로 배치 - 격자를 화면 래퍼에 다시 건다 (회귀 수정)

- 격자 대상을 `.rushhour.page[data-screen="play"]`에서 **플레이 화면 래퍼**로 옮긴다. 그러면 상단 줄·보드·조작이 격자 칸에 제대로 들어간다.
- 가로에서는 왼쪽 세로열에 조작, 오른쪽에 보드 묶음이 오는 지금 의도를 그대로 살린다.
- **겹침 0 · 잘림 0 · 페이지 스크롤 0**을 확인 조건으로 둔다.

**남은 것 하나(사용자 결정 대기).** 표준 4.7 규칙 5는 "좌·우 UI 열을 같은 폭으로 맞춰 게임판이 정중앙에 오게 한다"인데, 이 게임은 조작 열이 왼쪽에만 있고 오른쪽 짝이 없다. 지금은 격자째 가운데에 놓아 좌 209 / 우 225로 좁혔지만 보드 중심은 화면 중심에서 43px 오른쪽이다. 오른쪽에 같은 폭의 빈 열을 만들면 정중앙이 되는 대신 그만큼 자리를 버린다. 어느 쪽이 나은지는 눈으로 볼 문제라 **이 판에서 정하지 않는다.**

### 3.4. 조작 줄 - 위계를 실제 중요도에 맞춘다

| 자리 | 무엇 | 생김새 |
|---|---|---|
| 아래 줄(주 조작) | 되돌리기 · 힌트 · 리셋 | 크게(높이 44px 이상), 힌트가 강조색 |
| 그 아래(판 이동) | ‹ 이전 · 다음 › | 작게, 글자만. 진행 맵이 판을 고르는 자리이므로 여기서는 곁가지다 |

- **버튼을 없애지 않는다.** 이전·다음은 기능이라 지우는 것은 사용자 결정 영역이고, 이 판은 자리와 크기만 바꾼다.
- 되돌릴 것이 없어 꺼진 버튼은 지금처럼 회색이되, **꺼진 것이 켜진 것보다 눈에 띄지 않게** 한다.

### 3.5. 색 계통 - 셋으로 줄인다

- **강조색 하나**(출구 골드빛) - 힌트 버튼, 지금 판 표시, 진행 막대
- **바탕 하나**(크림) - 보드, 카드, 보통 버튼
- **배경 하나**(저녁 자주) - 그 뒤
- 초록 타이머 막대를 강조색 계열로 바꾼다. 흰 버튼은 크림 카드 톤으로 내린다. **지금 다섯 계통을 셋으로 접는다.**
- 배경은 단색을 유지한다. 무늬를 넣는 것은 이 판의 범위 밖이고, 넣으면 보드 안쪽 대비까지 함께 봐야 한다(B 몫).

## 4. 무엇으로 확인하는가

4.1. **기계 검사** - 이 판은 자리와 색이라 순수 로직 시험으로 잡히지 않는다. 기존 시험 10개 파일이 그대로 통과하는 것만 본다(회귀 없음 확인). **이 층이 화면을 못 본다는 사실을 결과에 적는다.**

4.2. **실측** - 2장의 표를 같은 스크립트로 다시 재고 아래를 확인한다.

- 네 크기 전부에서 겹침 0 · 페이지 세로 스크롤 0 · **잘려 나간 요소 0**
- 가로에서 오른쪽만 통째로 비던 것이 사라지고 좌우가 비슷해지는가
- 태블릿에서 보드가 680 근처로 커지는가
- **보드→조작** 빈칸이 지금보다 줄었는가
- 값이 길어져도(골드 다섯 자리 · 이동 세 자리) 보드 위 카드가 보드를 밀고 나가지 않는가

**1회차 검사가 잡은 확인 조건 오류 둘을 여기서 정정한다.**

(1) 처음에는 "가로에서 보드가 폭의 절반 이상"을 조건으로 적었는데 **실현 불가능한 값이었다.** 가로에서는 높이가 병목이라 430 높이에서 보드 최대치가 약 280px인데 폭의 절반은 466px이다. 조건을 "좌우가 비슷해지는가"로 바꾼다.

(2) 처음에는 "상단→정보 빈칸도 줄어야 한다"고 적었는데 **3.1과 정반대다.** 3.1이 "남는 세로를 위쪽으로 몬다"이므로 상단 빈칸은 늘어나는 것이 맞다. 이 조건을 뺀다 - 봐야 할 것은 빈칸이 한쪽으로 모였는가이지 양쪽이 다 줄었는가가 아니다.

4.3. **눈으로** - 네 크기 스크린샷을 지금 것과 나란히 놓고 본다. **화면 크기마다 다 본다** - 세로만 보고 넘어가 가로에서 깨진 것을 뒤늦게 잡은 적이 있다(걸음 B).

4.4. **밟는 경로** - 판 고르기 → 플레이 → 되돌리기 → 힌트 → 리셋 → 이전·다음 → 클리어 → 결과 카드 → 다시. 결과 카드가 덮을 때 **보드가 옆으로 튀지 않는가**도 함께 본다(걸음 B에서 실제로 난 회귀다).

## 5. 하지 말 것

5.1. 보드 안쪽을 건드리지 않는다 - 블록 그리기·캐릭터 크기·경계·출구 표현·표정. 전부 B 몫이다.

5.2. 공용 부품(`shared/frame/`)을 고치지 않는다. 이 판은 러시아워 폴더 안에서 끝난다.

5.3. 기능을 더하거나 빼지 않는다. 버튼 다섯은 다섯 그대로다.

5.4. 저장·진행·지갑·상점을 건드리지 않는다.

5.5. 상점·꾸미기·진행 맵 화면을 손대지 않는다. 이 판은 플레이 화면 하나다.

5.6. 배경에 무늬·그림을 넣지 않는다(3.5).

5.7. 다른 게임 여섯에 손대지 않는다.

## 6. 모델 배정

영속 데이터·공용 인터페이스·재화 어느 것도 안 걸린다. 다만 **틀려도 시험에 안 잡히고 화면으로만 드러나는 변경**이라 실측·눈 확인을 구현과 같은 판에서 돌린다.
