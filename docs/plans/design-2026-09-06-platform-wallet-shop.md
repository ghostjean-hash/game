# 걸음 C - 지갑과 상점 (설계)

작성: 2026-09-06 / 대상 일감: T-115 / 기준 문서: 기획서 Ⅲ권 4.5 · 4.6 · 4.7 · 8장 걸음 C

## 1. 이 설계가 하는 것과 안 하는 것

1.1. 하는 것 넷. **재화를 관리하는 지갑 부품**을 세우고, **상점 부품과 상점 화면**을 공용으로 만들고, **꾸미기를 상점의 값 없는 형태로** 세우고, 러시아워를 그 위로 올린다.

1.2. 하지 않는 것. 러시아워의 보상 계산식·가격·품목 목록·힌트가 무엇을 보여 주는지는 그대로 둔다. 껍데기 정리(팝업·버튼·효과의 공용화)는 걸음 D 몫이라 손대지 않는다 - 다만 이 판에서 통째로 사라지는 상점·꾸미기 팝업의 마크업과 그 둘만 쓰던 CSS는 함께 걷는다(쓰는 곳이 없어진 것을 남기는 것은 정리가 아니라 잔재다). 다른 게임 여섯은 이 판에서 아무 영향도 받지 않는다.

1.3. 걸음 A에서 세운 임시 변환기가 **여기서 완전히 사라진다.** 지갑·산 것·쓰는 것을 게임이 직접 읽던 자리가 부품 호출로 바뀌므로, `save-shape.js`에는 옛 저장을 옮기는 함수만 남는다.

1.4. 위험 등급은 높다. **재화를 다루고 영속 데이터를 읽고 쓰며 공용 인터페이스를 신설한다.** 셋 다 걸리므로 구현은 오퍼스다(10장).

## 2. 지갑 부품

2.1. 새 파일 `shared/frame/wallet.js`. `createWallet(...)` 하나를 내보낸다. 화면을 그리는 함수(`mount`)를 갖지만 부를 때만 화면을 만지므로 화면 없는 곳에서도 불러올 수 있다.

2.2. 게임이 넘기는 것.

| 이름 | 뜻 | 없으면 |
|---|---|---|
| `save` | 걸음 A의 저장 그릇 | 필수 |
| `currencies` | 재화 목록. 하나는 `{ id, label, icon }` | 필수 |
| `overlay` | 알림 쪽지를 띄울 그릇 | 쪽지 없이 조용히 거절 |
| `audio` | 거절 소리를 낼 그릇 | 소리 없음 |

**재화를 선언하지 않으면 지갑이 생기지 않는다**(기획서 4.5 첫 문단). 목록의 첫째가 기본 재화이고, 재화 하나만 쓰는 게임은 어느 호출에서도 재화 이름을 적지 않는다.

2.3. 부품이 돌려주는 것.

```
balance(cur?)                지금 잔액
earn(amount, { cur })        벌기. 새 잔액을 돌려준다
spend(amount, { cur, deny }) 쓰기. 모자라면 아무것도 빼지 않고 false
canAfford(amount, cur?)      쓸 수 있는가
refuse(cur?, deny)           모자란다고 알리기만 한다(빼지 않는다)
mount(parent, { cur })       잔액 표시 부품을 그 자리에 붙인다
onChange(fn)                 잔액이 바뀔 때 알림. 끊는 함수를 돌려준다
currencies                   재화 목록(넘긴 그대로)
```

2.4. `spend`가 이 부품의 중심이다. **모자랄 때 막고 알리는 것까지 플랫폼이 한다**(기획서 4.5).

- 잔액이 모자라면 **아무것도 빼지 않고** false를 돌려준다. 부분 차감은 없다.
- 그때 알림 쪽지(`골드가 모자라요`)와 거절 소리(`deny`)가 함께 나간다.
- `deny`에 화면 요소를 넘기면 그 요소를 흔든다. **흔들 자리를 정하는 것은 게임 몫이다**(부품은 공용, 자리는 게임 - 표준 규칙 19·20). 넘기지 않으면 흔들지 않는다.
- 음수·숫자 아닌 값은 받지 않고 false를 돌려준다. 재화가 음수로 내려가는 길을 만들지 않는다.

2.5. 쪽지 문구의 조사는 재화 이름의 받침을 보고 고른다(`골드가` / `코인이`). 한글 음절의 받침 유무는 코드포인트로 판정한다 - 재화 이름은 게임이 정하므로 문구를 게임마다 다시 적게 두지 않는다.

2.6. 잔액 표시 부품(`mount`)이 그리는 것은 아이콘 하나와 숫자 하나다. **어디에 놓을지는 게임이 정한다** - 플레이 화면 위든 상점 안이든 시작 화면이든 같은 부품을 붙인다. 잔액이 바뀌면 붙어 있는 표시가 전부 스스로 갱신된다.

2.7. **번 뒤 숫자가 올라가는 효과**는 이 표시 부품이 갖는다(기획서 4.5). 늘어날 때만 약 0.5초 동안 세어 올리고, 줄어들 때는 곧바로 바꾼다 - 쓴 것은 즉시 반영돼야 방금 무엇을 했는지가 분명하다. 움직임을 줄이도록 설정한 기기에서는 세어 올리지 않고 곧바로 바꾼다.

**어디에 붙였느냐에 따라 이 효과가 안 보일 수 있다**(구현 중 정정). 러시아워는 판을 깬 직후에 벌고 곧바로 결과 카드가 화면을 덮으므로, 상단에 붙은 잔액이 흐려진 채로 세어 올라가고 카드를 닫을 때는 이미 끝나 있다. 값은 언제나 맞고 이 게임은 결과 카드가 `+N 🪙`를 따로 알려 주므로 이번 판에서는 그대로 둔다. 잔액을 덮지 않는 게임에서는 그대로 보인다.

2.8. 저장은 걸음 A가 세운 `wallet` 칸 하나에 담긴다. **게임은 저장을 직접 만지지 않는다** - 이 부품을 지나야 계정 저장에 변경 신호가 간다(기획서 4.1 마지막 줄).

## 3. 상점 부품

3.1. 새 파일 둘로 나눈다. 진행 부품과 진행 맵을 나눈 것과 같은 이유다 - 규칙은 화면 없이 검사할 수 있어야 한다.

- `shared/frame/shop.js` - 무엇을 갖고 있고 무엇을 쓰는 중이며 살 수 있는가(순수 로직 + 저장)
- `shared/frame/shopcard.js` - 그것을 덮는 카드로 그리는 화면

3.2. 게임이 넘기는 것(상점 하나의 정의).

| 이름 | 뜻 | 없으면 |
|---|---|---|
| `id` | 상점 이름표. 시작 화면 추가 항목의 이름표가 된다 | 필수 |
| `title` | 카드 제목이자 추가 항목 글자 | 필수 |
| `currency` | 쓸 재화 이름표 | **꾸미기가 된다**(값 없는 형태, 4.7) |
| `kinds` | 종류 목록 | 필수 |
| `extraEl` | 카드 아래에 붙일 게임 조각을 돌려주는 함수 | 조각 없음 |
| `onEquip` | 쓰기로 정해졌을 때 알림 `(kindId, item)` | 알리지 않음 |

종류 하나는 `{ id, hint, equipLabel, pickLabel, defaultItem, items }`다. `hint`는 그 칸 위에 뜨는 한 줄, `equipLabel`은 쓰는 중인 것에 붙는 글자(`적용 중` / `장착 중`), `pickLabel`은 아직 안 고른 것에 붙는 글자다. `pickLabel`은 **구현 중에 더했다** - 값 없는 상점은 가격이 안 뜨므로 이것이 없으면 그 칸이 통째로 비어 누를 수 있다는 신호가 하나도 남지 않는다.

`defaultItem`은 **구현 중에 더했다.** 처음에는 저장이 비었을 때 첫 값 없는 품목을 쓰는 것으로 뒀는데, 그러면 화면에 보이는 차례가 곧 기본값이 된다. 러시아워의 블록 캐릭터는 목록 첫째가 포니이고 기본은 둘째인 밥풀이라, 그 규칙대로면 이미 놀던 사람의 캐릭터가 조용히 바뀐다. 기본을 종류가 직접 적고, 안 적었을 때만 첫 값 없는 품목으로 간다.

품목 하나는 `{ id, name, price, preview }`다. **`price`가 0이거나 없으면 처음부터 가진 것**이고, `preview(item)`은 미리 보기 조각을 돌려주는 함수로 **게임이 그린다**(기획서 4.6 마지막 줄).

3.3. **종류는 여러 개 중 하나만 쓰는 방식만 만든다.** 기획서 4.6은 여러 개를 함께 쓰는 종류와 안 쓴 상태를 허용하는 종류도 적어 두었지만, 그것을 쓰는 게임이 아직 없다. 쓰는 곳이 하나도 없는 공용 부품은 이번 조사에서 실제로 나온 실패 형태이므로(기획서 7.3 마지막 문단) 둘째 게임이 요구할 때 규격을 늘린다. 지금은 다른 방식을 넘기면 만들 때 바로 실패시켜 조용히 다르게 도는 것을 막는다.

3.4. 상점 부품이 돌려주는 것.

```
kinds                    종류 목록(넘긴 그대로)
items(kindId)            품목 목록
itemOf(kindId, itemId)   품목 하나
isOwned(kindId, itemId)  가졌는가(값 없는 품목은 언제나 참)
canBuy(kindId, itemId)   살 수 있는가(이미 가진 것은 언제나 참)
equipped(kindId)         쓰는 중인 것 이름표
equippedItem(kindId)     쓰는 중인 품목
select(kindId, itemId, { deny })   사거나 쓰기(3.5)
onChange(fn)             보유·장착이 바뀔 때 알림
```

3.5. `select`가 상점의 중심이다. 사는 것과 쓰는 것을 한 문으로 둔다 - 사람이 누르는 것은 품목 하나이고, 아직 없으면 사고 있으면 쓰는 것이 그 한 번의 뜻이다.

```
1. 이미 가진 것이면      → 쓰는 것으로 정하고 저장
2. 아직 없고 값이 있으면 → 낼 수 있는지 보고(모자라면 여기서 끝) 가진 것에 넣고
                          지갑에서 뺀 뒤 쓰는 것으로 정하고 저장
3. 결과를 돌려준다        { ok, bought, item }
```

- 모자랄 때의 거절·쪽지·흔들기는 지갑이 한다(2.4). 상점은 `deny`를 그대로 넘긴다.
- **물건을 먼저 남기고 값을 뒤에 뺀다**(구현 중 정정). 저장은 칸마다 따로 나가므로 "한 번에 내려쓴다"는 애초에 지킬 수 없는 약속이었다(저장 공간이 꽉 찬 순간 중간에 한 번이 실패할 수 있다). 순서를 이렇게 두면 최악이 '값이 안 빠졌는데 물건이 남는 것'이라 사용자가 잃지 않는다. 반대로 두면 골드만 빠지고 물건이 안 남아 되돌릴 길이 없다.
- 모자라서 끝나는 자리는 지갑의 **알리기만 하는 문**을 쓴다(2회차 검사 정정). 처음에는 거절을 일으키려고 빼기를 한 번 더 불렀는데, 그러면 낼 수 있는지 보는 식이 두 곳에 생겨 언젠가 갈린다.
- **상점은 저장을 캐시하지 않는다**(구현 중 정정). 진행 부품은 캐시를 갖지만 그것은 게임당 하나뿐이고, 상점은 여럿이 서는데 `owned`·`equipped`는 게임 전체가 나눠 쓰는 한 칸이다. 1회차 검사가 그 차이에서 나온 결함 둘을 재현했다 - 한 번도 안 읽은 캐시를 내려써 산 물건이 통째로 사라지는 것, 나중에 쓰는 쪽이 자기 스냅샷으로 상대의 선택을 되돌리는 것. 쓸 때도 자기가 손댄 종류 하나만 갈아 끼운다.
- 쓰기로 정해지면 `onEquip(kindId, item)`이 불린다. **그것이 화면에서 무엇을 바꾸는지는 게임이 안다**(보드 색인지 머리 장식인지 플랫폼은 모른다).

3.6. 값 없는 상점(꾸미기)에서는 모든 품목이 처음부터 가진 것이고, 가격도 잔액 줄도 그리지 않는다. 나머지 동작은 같다.

3.7. 저장은 걸음 A가 세운 `owned`·`equipped` 칸에 담긴다. 칸 안의 이름은 종류 이름표 그대로다(`theme` / `accessory` / `style`). **러시아워가 지금 쓰고 있는 이름과 같아서 저장 형식이 바뀌지 않는다** - 판 번호도 2 그대로다.

## 4. 상점 화면

4.1. 새 파일 `shared/frame/shopcard.js`. 공용 덮는 카드(`overlay.openCard`) 위에 그린다. **게임이 자기 팝업 껍데기를 만들지 않는다**(표준 규칙 19).

4.2. 공용이 그리는 것 - 카드 제목 · 잔액 줄(값 있는 상점만) · 종류별 칸 · 칸 위 한 줄 · 품목 격자 · 품목 하나(미리 보기 · 이름 · 가격 또는 쓰는 중 표시) · 살 수 없는 것의 흐린 표시 · 게임 조각 자리.

4.3. 잔액 줄은 지갑의 표시 부품을 그대로 쓴다(2.6). 상점에서 사면 그 자리 숫자가 바로 줄어든다.

4.4. 품목을 누르면 `select`가 돌고, 성공하면 격자를 다시 그린다. 실패하면 잔액 줄이 흔들린다 - 흔들 자리를 상점 화면이 정해 지갑에 넘긴다.

4.5. 게임 조각(`extraEl`)은 품목 격자 아래에 붙는다. 상점 규격에 맞지 않는 게임 고유 조작을 그 자리에 둔다 - 러시아워의 배경·테두리 켜고 끄기가 여기 온다(6.3).

4.6. 카드 겉모습은 지금 러시아워 상점과 눈에 띄게 달라지지 않게 맞춘다. **옮기는 판이지 다듬는 판이 아니다.**

## 5. 프레임 조립 연결

5.1. `createGameFrame`에 옵션 둘을 더한다.

- `wallet` - 재화 목록. 넘기면 지갑이 생기고 `frame.wallet`으로 닿는다
- `shops` - 상점 정의 목록. 넘기면 상점이 서고 `frame.shop(id)`로 닿는다

**둘 다 안 넘기면 아무 일도 일어나지 않는다**(기획서 2.2).

5.2. 값 있는 상점을 넘겼는데 지갑이 없으면 만들 때 바로 실패시킨다. 살 수 없는 상점이 조용히 서는 것보다 낫다. **재화 이름이 지갑에 없을 때도 같다**(구현 중 정정) - 그냥 두면 지갑이 기본 재화로 되돌려 값이 엉뚱한 재화에서 빠지는데 화면은 가격도 잔액도 안 그려 꾸미기처럼 보인다.

5.3. **상점은 시작 화면 추가 항목에 스스로 들어간다.** 환경설정이 이미 그렇게 하고 있고(규칙 20), 게임이 이름표와 여는 코드를 다시 적을 이유가 없다. 게임이 같은 이름표를 이미 적어 두었으면 중복해 넣지 않는다.

5.4. 상점을 여는 것도 조립이 맡는다 - 추가 항목이 눌리면 그 상점 카드가 뜬다. 게임의 `onExtra`는 게임이 직접 적은 항목에만 불린다.

| `renderSettings` / `setStyle` | 공용 상점(값 없는 형태) |
| `toggleBlockOpt` | 게임 조각으로 남는다(6.3) |
| `index.html`의 상점·꾸미기 팝업 마크업 | 지운다 |
| `style.css`의 상점·꾸미기 팝업 CSS | 지운다 |
| `assembleShape` / `scatterShape` | 지운다 |
| `progress()` / `saveProgress()` / `progCache` | 지운다 |
| `currentTheme` / `currentAccessory` / `currentStyle` | `frame.shop(…).equippedItem(…)` |
| `currentBlockOpts` | `save.readGame()` 직접(게임 칸이라 플랫폼이 안 본다) |
| 보드 규칙 · 풀이 · 조작 · 그리기 · 표정 · 시간 | 그대로 게임 몫 |

6.2. 상점 정의 둘을 넘긴다.

- **상점**(`gold`) - 보드 무늬 다섯, 머리 장식 열여섯. 미리 보기는 지금 그리던 색 조각과 그림 글자 그대로다
- **꾸미기**(값 없음) - 블록 캐릭터 둘. 미리 보기는 지금 쓰던 그림 글자다

6.3. **배경·테두리 켜고 끄기는 꾸미기 카드의 게임 조각으로 남는다.** 이것은 그림을 고르는 것이 아니라 켜고 끄는 것이라 상점의 사고 쓰는 모델에 맞지 않는다 - 저장도 이미 게임 칸에 있다(걸음 A에서 그렇게 뒀다). 지금은 캐릭터 줄마다 토글이 붙어 있는데, 고르기 격자를 공용이 그리므로 **토글 세 줄(포니 · 밥풀이 · 주인공)이 격자 아래로 내려간다.** 항목과 값은 하나도 바뀌지 않는다.

6.4. 잔액 표시는 플레이 화면 위 지금 그 자리에 붙인다. 표시 부품이 만드는 조각을 지금의 알약 안에 넣으므로 **겉모습이 달라지지 않는다.**

6.5. 시작 화면 기록 줄의 골드도 지갑에서 읽는다.

6.6. **화면이 지금보다 나빠지지 않아야 한다**(기획서 6.3의 넷째 조건). 품목 칩 크기·색·격자 간격·잔액 줄 자리가 눈에 띄게 달라지면 그것 자체가 결함이다.

## 7. 저장은 어떻게 바뀌나

7.1. **저장 형식은 바뀌지 않는다.** `wallet`·`owned`·`equipped` 칸의 모양과 그 안의 이름이 지금 그대로라, 이미 놀고 있는 사람의 골드와 산 물건이 그 자리에 그대로 있다.

7.2. 그래서 **판 번호를 올리지 않고 옮기기 함수도 건드리지 않는다.** 옮기기는 옛 저장을 위한 것이고 이 판에서 옛 저장이 늘지 않는다.

7.3. 바뀌는 것은 **읽고 쓰는 주체**뿐이다. 지금은 게임이 변환기를 거쳐 한 덩어리로 읽고 통째로 내려썼는데, 앞으로는 지갑과 상점이 자기 칸만 만진다. 통째로 내려쓰던 자리가 사라지므로 **한 값을 고칠 때 다른 값이 옛 것으로 되돌아갈 길도 함께 사라진다.**

## 8. 무엇으로 확인하는가

8.1. **기계 검사** - 새 시험 둘을 만든다. 둘 다 화면 없이 돈다.

`tests/wallet.test.mjs`
1. 벌면 잔액이 늘고 저장에 남는가
2. 쓰면 줄고, 모자라면 **한 푼도 안 빠지고** 거절되는가
3. 음수·숫자 아닌 값이 거절되는가
4. 재화가 여럿일 때 서로 섞이지 않는가
5. 저장이 비었거나 깨져 있어도 0에서 시작하는가

`tests/shop.test.mjs`
6. 값 없는 품목이 처음부터 가진 것인가
7. 사면 잔액이 값만큼 빠지고 보유·장착이 함께 남는가
8. 모자라면 잔액도 보유도 하나도 안 바뀌는가
9. 이미 가진 것을 누르면 값이 안 빠지고 쓰는 것만 바뀌는가
10. 종류가 여럿일 때 서로 섞이지 않는가
11. 값 없는 상점(꾸미기)에서 지갑 없이도 고르기가 되는가
12. 지갑 없이 값 있는 상점을 세우면 만들 때 실패하는가
13. 하나만 쓰는 방식이 아닌 종류를 넘기면 만들 때 실패하는가

기존 시험 여덟은 그대로 통과해야 한다. 특히 `tests/save.test.mjs`가 옮기기를 보고 있으므로 저장 형식이 안 바뀐 것이 여기서 걸러진다.

8.2. **실화면** - 러시아워를 실제 브라우저로 연다. 이 판의 진짜 합격 조건이다(기획서 9.2).

- 이미 있던 골드와 산 물건이 그대로 있는가
- 판을 깨면 골드가 늘고 **숫자가 세어 올라가는가**
- 상점을 열어 살 수 있는 것을 사면 잔액이 줄고 바로 적용되는가
- 골드가 모자란 것을 누르면 거절되고 쪽지가 뜨며 잔액이 안 줄어드는가
- 이미 산 것을 누르면 값이 또 빠지지 않고 바꿔 끼워지는가
- 힌트가 골드를 제대로 빼고, 모자라면 거절되는가
- 꾸미기에서 캐릭터를 바꾸면 보드가 다시 그려지는가
- 꾸미기의 배경·테두리 켜고 끄기가 전과 같이 도는가
- 상점·꾸미기에서 되돌아가기가 **한 칸씩만** 물러나는가(연타 포함)
- 나갔다 다시 들어와도 잔액·산 것·쓰는 것이 그대로인가
- 세로와 가로 둘 다에서 넘치지 않는가

8.3. **다른 게임 여섯** - 시작 화면과 플레이가 그대로인지 확인한다. 지갑·상점을 안 넘겼으므로 아무 변화도 없어야 한다.

## 9. 하지 말 것

9.0. 새 공용 파일을 만들면 **오프라인 목록과 캐시 판 번호를 함께 올린다**(`service-worker.js`). 안 올리면 다시 온 사람이 옛 조립 파일을 받고, 홈 화면에 추가한 사람은 오프라인 첫 실행에서 없는 파일을 불러오다 흰 화면이 된다. 걸음 B가 한 것과 같은 자리다.

9.1. 저장 형식과 판 번호를 바꾸지 않는다. 옮기기 함수를 건드리지 않는다.

9.2. 러시아워의 가격·보상 값·품목 목록·힌트 값을 바꾸지 않는다.

9.3. 상점·꾸미기의 겉모습을 개선하지 않는다. 옮기는 판이지 다듬는 판이 아니다.

9.4. 여러 개를 함께 쓰는 종류·안 쓴 상태를 허용하는 종류를 만들지 않는다(3.3).

9.5. 도감(기획서 4.7 뒷부분)을 만들지 않는다. 쓰는 게임이 없다.

9.6. 표준 움직임 효과의 공용화(기획서 4.8)를 하지 않는다. 걸음 D 몫이다 - 숫자 올라감만 지갑 표시 부품 안에 든다.

9.7. 다른 게임 여섯에 지갑·상점을 붙이지 않는다(걸음 E 뒤).

9.8. 진행 부품과 진행 맵을 건드리지 않는다(걸음 B에서 닫혔다).

9.9. 러시아워에 남아 있는 팝업 껍데기·아이콘 버튼 정의를 이 판에서 걷지 않는다 - 걸음 D 몫이다. 상점·꾸미기 팝업이 통째로 사라지면서 그 둘만 쓰던 것이 함께 사라지는 것은 잔재 제거이지 걸음 D의 정리가 아니다.

**구현 중 정정 둘.** (1) 러시아워의 팝업 껍데기 CSS(`.modal` · `.modal-backdrop` · `.modal-x`)를 쓰던 곳이 상점과 꾸미기뿐이어서, 그 둘이 가면서 통째로 쓰이지 않게 됐다. 남기면 그것이 곧 잔재라 함께 걷었다. (2) 이 게임의 거절 흔들기(`rh-shake`)도 쓰던 곳 둘이 다 사라졌다 - 골드 알약은 이제 지갑이 공용 흔들기로 흔들고, 상점 잔액 줄은 공용 화면 것이다. 남은 자리 하나(고난도 퍼즐이라 힌트를 막는 곳)를 공용 흔들기로 옮기고 이 게임 얼개를 지웠다. 그 자리는 원래 흔들기 규칙이 없어 아무 일도 일어나지 않던 곳이라 함께 살아났다.
