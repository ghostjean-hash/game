# 걸음 B - 진행과 진행 맵 (설계)

작성: 2026-09-06 / 대상 일감: T-115 / 기준 문서: 기획서 Ⅲ권 4.2 · 4.3 · 4.4 · 8장 걸음 B

## 1. 이 설계가 하는 것과 안 하는 것

1.1. 하는 것 셋. **판 목록을 받아 진행을 관리하는 부품**을 세우고, **진행 맵 화면을 공용으로** 만들고, 러시아워를 그 위로 올린다.

1.2. 하지 않는 것. 지갑·상점·꾸미기는 걸음 C 몫이라 손대지 않는다. 러시아워의 플레이 규칙·연출·보상 값도 그대로 둔다. 다른 게임 여섯은 이 판에서 아무 영향도 받지 않는다(진행 부품을 넘기지 않은 게임에는 생기지 않는다).

1.3. 걸음 A에서 세운 임시 변환기는 **절반이 걷힌다.** 진행·별·최고 기록·현재 위치를 게임이 직접 읽던 자리가 부품 호출로 바뀌므로, 변환기에는 지갑·상점 몫만 남는다.

1.4. 위험 등급은 중간이다. 영속 데이터를 읽고 쓰지만 걸음 A가 세운 저장 칸 위에서만 움직이고 형식을 바꾸지 않는다. 다만 **공용 인터페이스 신설**이라 구현은 오퍼스다.

## 2. 진행 부품

2.1. 새 파일 `shared/frame/progress.js`. `createProgress(...)` 하나를 내보낸다.

2.2. 게임이 넘기는 것.

| 이름 | 뜻 | 없으면 |
|---|---|---|
| `save` | 걸음 A의 저장 그릇 | 필수 |
| `modes` | 갈래 목록. 하나면 갈래가 없는 게임이다. 갈래 하나는 `{ id, name, stages, credit }` | 필수 |
| `group` | 판 하나를 받아 묶음 이름을 돌려주는 함수 | 묶음 없이 한 줄로 본다 |
| `groups` | 묶음 순서와 보일 이름 `[{ id, label }]` | `group`이 돌려준 순서대로 |
| `stars` | 별 매기는 방식(3장) | 별 없음 |
| `unlock` | 잠금 방식(3장) | 잠금 없음 |

판 하나(`stages`의 원소)는 게임이 정한 모양 그대로다. **플랫폼이 요구하는 것은 `id` 하나뿐**이고 나머지(격자·난이도·기준값)는 들고만 있다가 그대로 돌려준다.

2.3. 부품이 돌려주는 것.

```
mode                지금 갈래 id
setMode(id)         갈래 바꾸기(저장에 남는다)
modes               갈래 목록
stages(modeId?)     판 목록
byId(id, modeId?)   판 하나
of(id, modeId?)     그 판의 기록 { cleared, stars, best }
current(modeId?)    마지막으로 열었던 판 id
setCurrent(id)      그 값 남기기
finish(id, result)  한 판이 끝났다고 알리기(2.4)
totals(modeId?)     { cleared, total, stars }
isUnlocked(id, modeId?)
next(id) / prev(id) 다음·이전 판(없으면 null)
extra(modeId?) / setExtra(obj)  갈래별 게임 고유 값. 플랫폼은 안 본다
```

2.4. `finish(id, result)`가 이 부품의 중심이다. 게임은 한 판이 끝났다는 사실과 결과만 넘기고, 저장·별·최고 기록은 플랫폼이 한다.

```
result = { cleared, value, par, mistakes }   // 쓰는 것만 넘긴다
반환   = { stars, isNewBest, isFirstClear, prevBest }
```

- `value`는 그 판의 성적이다(이동 수·걸린 시간·점수). 작을수록 좋은지는 `stars` 방식과 함께 게임이 한 번 정한다.
- 최고 기록은 **더 좋을 때만** 바뀌고, 별은 **더 많을 때만** 바뀐다. 한 번 3별을 받은 판을 대충 다시 깨도 별이 깎이지 않는다(지금 러시아워 동작 그대로).
- 게임은 반환값으로 결과 카드를 채우고 보상을 계산한다. **보상 계산은 게임 몫이다**(기획서 4.5).

## 3. 별과 잠금

3.1. 별 방식 넷. 기획서 4.4가 정한 그대로다.

| 값 | 규칙 | 게임이 함께 넘길 것 |
|---|---|---|
| 없음(기본) | 깼다·못 깼다만 | - |
| `{ type:'par', margin }` | 기준값 이내 3, `margin` 이내 2, 그 밖 1 | `finish`에 `par` |
| `{ type:'mistakes', two, one }` | 틀린 수로 깎는다 | `finish`에 `mistakes` |
| 함수 | 결과를 받아 별 수를 돌려준다 | - |

3.2. 잠금 방식 넷.

| 값 | 규칙 |
|---|---|
| 없음(기본) | 모든 판이 처음부터 열린다. 러시아워가 여기 |
| `'sequential'` | 앞 판을 깨야 다음이 열린다 |
| `{ type:'stars', per }` | 묶음마다 별을 `per`개 모아야 다음 묶음이 열린다 |
| 함수 | 판과 진행을 받아 열렸는지 돌려준다 |

3.3. 잠긴 판은 `isUnlocked`가 false를 돌려주고, 진행 맵이 자물쇠로 그리며 눌러도 들어가지 않는다(거절 흔들기 + 알림 쪽지).

## 4. 진행 맵 화면

4.1. 새 파일 `shared/frame/mapscreen.js`. 선택 화면(`SCREEN.SELECT`) 안에 그린다.

4.2. 공용이 그리는 것 - 갈래 탭 · 출처 한 줄 · 요약 줄(`클리어 N / M · 모은 별 K`) · 묶음별 칩 격자 · 칩 하나(번호 · 별 · 깬 표시 · 지금 위치 · 자물쇠).

4.3. **갈래를 고르는 방식은 지금 러시아워 것을 규격으로 삼는다.** 탭을 누르면 그 갈래의 진행을 미리 보기만 하고, 실제 전환은 그 갈래의 판을 골랐을 때 확정된다. 보다가 그냥 나가면 갈래가 바뀌지 않는다.

4.4. 게임이 바꿀 수 있는 것 둘.

- `renderChip(stage, record)` - 칩 안에 무엇을 그릴지. 안 넘기면 번호와 별을 그린다
- `label(stage)` - 칩에 쓸 번호 대신 다른 이름

4.5. **겉모습을 한 가지로 고정하지 않는다**(기획서 4.3). 칸 격자가 기본값이고, 게임이 직접 그리겠다고 하면 플랫폼은 상태만 준다. 그 갈래는 비행 슈팅의 세계 지도가 올라올 때 실제로 쓰인다 - 이번 판에서는 **자리만 만들고 러시아워는 기본값을 쓴다.**

4.6. 자리 잡는 규칙(어디에 놓는가)은 게임이 계속 갖는다. 공용은 화면 한 칸과 그 안의 구조만 준다.

## 5. 프레임 조립 연결

5.1. `createGameFrame`에 `progress` 옵션을 더한다. 넘기면 조립이 진행 부품을 만들고 선택 화면에 맵을 붙인다. **안 넘기면 아무 일도 일어나지 않는다**(기획서 2.2).

5.2. 넘기면 따라오는 것 셋.

- `frame.progress` - 진행 부품
- 선택 화면에 진행 맵이 서고, 판을 고르면 `onPick(stage)`가 불린다
- 시작 화면 이어서 하기가 `current`를 보고 저절로 채워진다(게임이 `setResume`을 부르지 않아도 된다)

5.3. `hasSelect`는 지금처럼 게임이 정한다. 진행을 넘기면서 `hasSelect`를 켜지 않으면 맵이 설 자리가 없으므로 조립이 켜 준다.

## 6. 러시아워 적용

6.1. 무엇이 어디로 가는가.

| 지금 | 가는 곳 |
|---|---|
| `MODES` 배열(갈래 정의) | `progress.modes`로 넘긴다 |
| `modeProg()` / `mp.cleared` / `mp.stars` / `mp.best` | `frame.progress.of(id)` |
| `mp.current` 읽고 쓰기 | `frame.progress.current()` / `setCurrent(id)` |
| `starsFor(moves, optimal)` | `stars: { type:'par', margin: STAR2_MARGIN }` |
| `onSolved`의 기록 갱신 다섯 줄 | `frame.progress.finish(id, { cleared:true, value:moves, par:optimal })` |
| `go(delta)` | `frame.progress.next(id)` / `prev(id)` |
| `openMap` / `renderMap`(41줄) | 공용 진행 맵 |
| `mapViewMode`와 탭 처리 | 공용 진행 맵 |
| `index.html`의 진행 맵 마크업 | 지운다 |
| `mp.combo` / `mp.bestCombo` | `frame.progress.extra()` / `setExtra()` |
| 클리어 보상 계산 | 그대로 게임 몫 |
| `loadPuzzle` / 보드 · 타이머 · 표정 | 그대로 게임 몫 |

6.2. 칩 안 내용은 지금과 같게 그린다(번호 + 별). 묶음은 난이도 넷이고 이름도 지금 그대로다.

6.3. **화면이 지금보다 나빠지지 않아야 한다.** 칩 크기·색·묶음 제목·요약 줄 문구가 눈에 띄게 달라지면 그것 자체가 결함이다.

## 7. 어댑터는 얼마나 걷히나

7.1. 걸음 A가 세운 변환기에서 **진행 몫이 사라진다.** `assembleShape`·`scatterShape`가 다루던 것 중 `modes`(깬 판·별·최고 기록·현재 위치·연속 클리어)가 통째로 빠지고, 지갑·산 것·쓰는 것·게임 칸만 남는다.

7.2. 남는 변환기는 걸음 C에서 마저 걷힌다. 그때 `save-shape.js`에는 옮기기 함수만 남는다.

7.3. **옮기기 함수는 건드리지 않는다.** 저장 형식이 바뀌지 않으므로 판 번호도 그대로 2다.

## 8. 무엇으로 확인하는가

8.1. **기계 검사** - `tests/progress.test.mjs`를 새로 만든다. 부품이 순수 로직이라 화면 없이 돌릴 수 있다.

1. 판을 깨면 깬 표시·별·최고 기록이 남는가
2. 더 나쁜 성적으로 다시 깨도 별과 최고 기록이 깎이지 않는가
3. 별 방식 넷이 각각 규칙대로 매기는가
4. 잠금 방식 넷이 각각 규칙대로 막는가
5. 갈래를 바꾸면 그 갈래의 진행만 보이는가
6. 다음·이전이 목록 끝에서 null을 돌려주는가
7. 갈래별 게임 고유 값이 따로 담기는가
8. 진행 부품을 안 넘긴 게임에는 아무 일도 없는가

8.2. **실화면** - 러시아워를 실제 브라우저로 연다. 이 판의 진짜 합격 조건이다.

- 진행 맵이 전과 같아 보이는가(칩·별·묶음 제목·요약 줄)
- 깬 판의 별이 전과 같은가(두 갈래 다)
- 탭으로 다른 갈래를 봐도 갈래가 바뀌지 않고, 판을 고르면 그때 바뀌는가
- 판을 깨면 별·최고 기록이 갱신되고 골드가 늘어나는가
- 다음·이전으로 판을 넘길 수 있는가
- 이어서 하기가 마지막 판을 가리키는가
- 되돌아가기가 맵에서 시작 화면으로 한 칸만 물러나는가

8.3. **다른 게임 여섯** - 시작 화면과 플레이가 그대로인지 확인한다. 진행을 안 넘겼으므로 아무 변화도 없어야 한다.

## 9. 하지 말 것

9.1. 지갑·상점·꾸미기를 건드리지 않는다(걸음 C).

9.2. 저장 형식과 판 번호를 바꾸지 않는다.

9.3. 러시아워의 플레이 규칙·보상 값·난이도·연출을 바꾸지 않는다.

9.4. 진행 맵의 겉모습을 개선하지 않는다. 옮기는 판이지 다듬는 판이 아니다.

9.5. 다른 게임 여섯에 진행 부품을 붙이지 않는다(걸음 E 뒤).

9.6. 잠금·별을 러시아워에 새로 넣지 않는다. 지금 잠금이 없으므로 없는 채로 옮긴다.

9.7. 게임이 직접 그리는 지도 갈래를 이번에 구현하지 않는다. 자리만 만든다.

## 10. 모델 배정

공용 인터페이스 신설 + 영속 데이터를 읽고 쓴다. **구현도 오퍼스다.**
