# html-game 표준 변경 이력

# 1. v0.4.3 (2026-08-24)

1.1. Fullscreen API 토글·자동 복귀·홈 화면 추가 안내를 폐기하고, display: standalone 기반 설치형 앱 셸로 전환했다.
1.2. 공용 게임 상단 띠는 폐기하고, 되돌아가기 + `⋯` 떠다니는 메뉴 구조로 정의했다. 허브·앱의 주 이동은 하단 도크를 쓴다.
1.3. 테트리스·스도쿠·러시아워 플레이 HUD도 화면 폭을 가르는 띠를 쓰지 않고, 보드 위 독립 카드로 전환했다.
1.4. 모든 공용 프레임 게임에 화면과 무관하게 작동하는 `허브` 이동 버튼을 추가했다.

1.5. 실측 사고 하나 - 프레임이 미리 만들어 둔 빈 화면 자리가 게임 화면과 같은 이름으로 남아 둘 다 표시되어 화면 높이를 반씩 나눠 가졌다(비행 슈팅에서 보드가 절반 크기로 드러남). `register`가 앞 자리의 이름표를 떼도록 공용에서 고쳤고 회귀 테스트로 고정했다.

# 4. v0.3.5 (2026-07-31)

3.1. 4.7 규칙 6 보강: 막힌 기기 안내를 글로만 쓰는 것을 금지. 눌러야 할 버튼 모양을 그린 단계 그림 + 그 도구 모음 방향을 가리키는 화살표를 함께 둔다. 브라우저별로 그림·문구·화살표 방향을 갈라 쓴다(사파리 = 아래 도구 모음 가운데 / 아이폰 크롬 = 주소창 오른쪽 메뉴).
3.2. 변경 사유: 사용자 지적 - "홈 화면 아이콘 실행을 일반 유저는 알 수 없잖아." v0.3.4 안내는 글 설명이라 방법을 아는 사람만 따라할 수 있었다. 아이폰에서 일반 사용자가 아무 조작 없이 전체화면을 얻는 길은 애플이 열어두지 않았으므로, 웹이 할 수 있는 최선은 "따라할 수 있게 보여주는 것"이고 그 품질이 곧 도달률이다.
3.3. 구현: `shared/fullscreen.js` - `homeScreenHintText` → `homeScreenHintGuide`(3단계 + pointer 방향 + note), 버튼 그림 인라인 SVG 4종(공유·메뉴 점 세 개·홈 화면에 추가·앱 아이콘), 카드 위치를 화살표가 가리키는 쪽에 붙임(사파리 아래 / 크롬 위), "알겠습니다" 확인 버튼, 움직임 최소화 설정 존중(prefers-reduced-motion).
3.4. 검증: `tests/fullscreen.test.mjs` 14 → 16건(3단계 구조·브라우저별 화살표 방향·그림 3컷 인라인 SVG·확인 버튼 닫기) + smoke 정적 검사 2건 추가(29 통과). 아이폰 사파리·아이폰 크롬 두 경우를 실브라우저로 렌더해 카드·화살표가 화면 안에 들어오는지 좌표로 확인하고 스크린샷 3장(라이트 허브 2종·다크 게임)으로 대비·가독성 확인. 첫 시도에서 화살표가 화면 밖으로 나가 카드 여백을 34px 확보하는 수정을 거쳤다.
3.5. 영향: 허브 첫 화면 + 게임 5개(공용 모듈 경유 자동). 전체화면이 지원되는 아이패드·안드로이드·PC는 안내가 뜨지 않아 무영향.
# 5. v0.3.4 (2026-07-31)

4.1. 4.7 규칙 6 보강: 전체화면이 막힌 기기(아이폰)에서 버튼을 조용히 감추는 처리를 금지. 버튼을 남겨 누르면 홈 화면 추가 안내를 띄우고, 허브 첫 화면에서도 첫 방문 1회 알린다. 공용 구현 `shared/fullscreen.js`의 `showHomeScreenHint`·`homeScreenHintText`(브라우저별 경로 문구 분기).
4.2. 변경 사유: 사용자가 "아이폰 크롬에서는 전체화면이 안 된다"고 보고. 진단 결과 우리 결함이 아니라 애플 정책이었다 - 아이폰은 동영상 외 전체화면을 열지 않고, 아이폰의 모든 브라우저가 Safari 엔진을 쓰도록 강제돼 크롬으로 바꿔도 같다. v0.3.3 구현은 그런 기기에서 버튼을 감췄고, 사용자에게는 "안 된다"로만 보여 유일한 대안(홈 화면 추가)에 도달할 길이 없었다. 사용자가 "모든 사람이 쓰게 하고 싶다"고 결정해 화면 안 안내로 승격.
4.3. 검증: `tests/fullscreen.test.mjs` 10 → 14건(막힌 기기 버튼 유지·안내 연결 / 브라우저별 문구 분기 / 첫 방문 1회 / 중복 표시 방지 / 홈 화면 앱에서는 안내 없음) + smoke 정적 검사 3건 추가(29 통과). 아이폰 흉내 실브라우저 실측 - 허브 첫 방문 안내 표시·닫기 후 재방문 미표시, 게임 화면 버튼 유지 및 눌러 안내 표시, 홈 화면 앱 실행에서는 버튼·안내 모두 없음. 스크린샷 2장(라이트 허브·다크 게임)으로 대비·화면 안 배치 확인.
4.4. 영향: 허브 첫 화면 + 게임 5개(공용 모듈 경유 자동 적용). 아이패드·데스크톱은 전체화면이 지원되므로 안내가 뜨지 않아 무영향.
# 6. v0.3.3 (2026-07-31)

5.1. 4.7 규칙 6 강화: "전체화면" → "전체화면 - 켜는 것보다 유지가 어렵다". 버튼 제공·미지원 숨김에 더해, 브라우저가 조작 중 임의로 해제한 것을 감지해 다음 사용자 조작에서 되돌리도록 의무화. 사용자가 버튼·ESC로 끈 것은 되돌리지 않는다. 구현은 게임별 재작성 금지, 공용 모듈 `shared/fullscreen.js` 사용.
5.2. 4.7 규칙 8 신설: "홈 화면 앱 실행". 게임 화면마다 자기 `app.webmanifest`(display: fullscreen / start_url './' / scope 허브 루트) + `apple-mobile-web-app-capable`. 허브 첫 화면에만 두면 게임 화면에서 홈 화면에 추가할 때 브라우저 껍데기가 붙어 열린다.
5.3. 변경 사유: 사용자가 아이패드에서 전체화면으로 플레이해도 조작 중 금방 풀린다고 보고. 원인 둘 - (a) 아이패드 Safari·Chrome이 가장자리 스와이프·여러 손가락 제스처·회전에 전체화면을 스스로 끝내는데 기존 구현은 해제를 감지하지 않아 사용자가 버튼을 다시 눌러야 했다. (b) 우회로인 홈 화면 추가도 게임 화면 다섯 곳에 manifest 링크가 없어 반쪽이었다(노노그램은 애플용 표식도 없었다).
5.4. 검증: `tests/fullscreen.test.mjs` 10건 신설(복귀·사용자 의사 존중·재시도 한도·접두 API·홈 화면 앱 판별) + `tests/smoke.mjs` 정적 검사 확장(공용 모듈 사용 강제·옛 인라인 구현 부활 차단·8개 화면 홈 화면 앱 설정). 실브라우저(Chrome) 신뢰 입력 실측 - 전체화면 진입 → 강제 해제 → 조작 후 자동 복귀 확인, 버튼으로 끈 뒤에는 복귀하지 않음.
5.5. 영향: 게임 5개 + 앱 3개에 적용(공용 모듈 배선 + app.webmanifest). 적용 프로젝트 lotto는 표준 대상이라 v0.3.2 → v0.3.3 마이그레이션 여부 사용자 결정(3.2 절차). 아이패드 실기기 체감은 사람만 측정 가능 - 사용자 실측 대기.

# 7. v0.3.2 (2026-07-06)
